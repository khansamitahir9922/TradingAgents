## Goal
Let the Core Engine turn an APPROVED intent version into one Order (NEW), in one transaction with `APPROVED → CONVERTED` and the outbox row. The order pins the references the gate compares against later. The task also records cancel requests from a named operator as command rows (G1 step 10; G2; G3; PRD UC-07; D31).

## Contracts
```python
@dataclass(frozen=True)
class ConversionReport:
    converted: tuple[Order, ...]
    skipped: tuple[tuple[str, int, str], ...]   # (intent_id, version, reason): not latest, not APPROVED,
                                                # approval expired, already converted, stale write
def convert_approved(account_id: str, *, at: datetime, stores: ControlStores, orders: OrderStore) -> ConversionReport
def request_cancel(order_id: str, *, operator_id: str, reason: str, command_at: datetime,
                   stores: ControlStores, orders: OrderStore) -> CancelRequest

# portfolio/fingerprint.py
def economic_fingerprint(*, cash: Decimal, positions: Sequence[tuple[str, Decimal]],
                         reservations: Sequence[Reservation]) -> str      # "pfp-" + SHA-256; no valuation, time or provenance
def fingerprint_of(snapshot: PortfolioSnapshot) -> str                    # declared: no reservations; provisional: M4-09
class FingerprintProvider(Protocol):
    def at(self, account_id: str, at: datetime, *, excluding_order: str | None) -> str | Unavailable
class DeclaredFingerprints(FingerprintProvider): ...                      # declared start only; replaced in M4-09
```
The fingerprint covers only economic content: cash, whole-share positions and open-order reservations. It excludes valuation, `as_of`, peak and provenance, so an unchanged portfolio gives the same fingerprint at any time (Codex B4).

## Rules
1. **One transaction per intent version**, under the account-control lock (M3-05 rule 6; the lock protocol is M4-05 rule 4). It re-reads the intent, which must be the latest version and APPROVED, with its approval unexpired at `at`. It then:
   1. writes `APPROVED → CONVERTED` (compare-and-set);
   2. creates the order with deterministic ids;
   3. pins `intent_content_id` (the approved version's content id) and `position_fingerprint = fingerprint_of(the intent's snapshot)`. That is the economic state the proposal was decided on. When the proposal was made this order didn't exist, so it is consistently excluded (M4-05 rule 3);
   4. adds `order.created`.

   A failure at any point writes nothing.
2. **The order copies the approved version exactly** (Law 12). Nothing is recomputed, and the intent's lineage is the order's lineage (Law 18).
3. **Only APPROVED becomes an order** (Part J). Every other case is listed in `skipped`, with its reason, and is never an error.
4. **Accounts** (D22, D23). RESEARCH converts at its replay time. PAPER converts at live time, but its intents can't reach APPROVED in M4 (M3's promotion check still rejects them).
5. **Cancel requests** (D31). The operator must be an active ADMIN or TRADER at `command_at` (LiveClock). The order must not be in a final state. The request is created as version 1 of a cancel-request aggregate, with `cancel.requested`, in one transaction, and is audited. No order state changes; only the Execution Worker acts (G3, M4-07 rule 3). It is accepted whatever the kill switch says (Law 15).
6. **Lifting the M3 refusal.** `APPROVED → CONVERTED` is legal only inside `convert_approved`. A bare `transition(..., CONVERTED)` is still refused.

## Acceptance tests
- Happy path: CONVERTED, NEW and `order.created` in one transaction; the fields match the version exactly; `intent_content_id` and `position_fingerprint` are pinned.
- Fault injection after each write inside the transaction: nothing is left behind.
- Each `skipped` reason occurs, with its intent and version, and none raises.
- Concurrent conversion of one version on PostgreSQL: one order; the other is reported as already converted.
- Cancel: a Viewer, an inactive operator and a final order are refused. A valid request leaves the order state and version unchanged. It is accepted while trading is disabled.

## Out of scope
Acting on a cancel (M4-07), Level 1 approval itself (M3-13, unchanged).
