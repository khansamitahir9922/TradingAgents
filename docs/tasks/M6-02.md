## Contracts

The [M6 shared contracts](M6-README.md#shared-contracts) govern this task.

1. Tables per C2; UPDATE/DELETE/TRUNCATE refused; `research-worker` role trigger for claims, finishes, records, contexts and usage; REQUESTED and budget policy written by Core/Admin paths only.
2. Job claim is compare-and-set with a lease; an expired lease can be re-claimed and the earlier claim's late finish is refused.
3. Record + context + usage + outbox event commit in one transaction; an injected failure at each write leaves nothing.
4. Additive upgrade from a populated 0020 database preserves every row.

## Implementation/check record

Additive schema 0021 and ResearchStore. Append-only research tables (jobs, job versions, records, contexts, budget policies, budget usage); UPDATE/DELETE/TRUNCATE and conflict-update refused. Writers fixed by process role in SQL: core-engine requests, expires unclaimed jobs and sets budget policy; research-worker claims, finishes, saves records/contexts and usage. Job versions are compare-and-set (primary key per version) and the SQL trigger mirrors the contract's edge table, at most one re-claim, re-claim only after lease expiry with a new run, finish only by the current claim holder for its own run, SUCCEEDED only with its record and exactly its context. A finished run's record, context, ACTUAL usage, final version and `research.completed` event commit together. Requests are attributed to the authorizing operator's audit Actor (authorization itself is M6-08).

Design note for M6-07: the lease covers the whole bounded run (deadline plus margin), so a running job is never renewed in place; a crashed run's lease expires and the job can be re-claimed once.

## Implementation/check record

Codex review B11 (bundles not bound to their job), fixed. `finish` now requires the record's settings to equal the job's frozen settings, and the context to be for the job's instrument, generated exactly when its run finished. Reads (`context`, `latest_context`) return a context only when its job recorded that run as SUCCEEDED, and re-check the binding. Additive migration 0022 enforces the same at insert in SQL: a record must be the job's current claimed run, with the matching attempt and the job's settings; a context needs its run's SUCCEEDED record, the still-current claim, the job's instrument and the run's finish time. A context added after a FAILED (or any terminal) version is therefore refused, so the invariant can't be broken later. 0021 is unchanged.

The new checks also exposed my own fixture inconsistency (contexts dated before their run finished) and one test reading research "as of" a time before it existed; both corrected, the latter now asserting None before generation. The upgrade proof now carries a complete research bundle from 0021 to the latest schema, preserving every row and keeping the context readable.
