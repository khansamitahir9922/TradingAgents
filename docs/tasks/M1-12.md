## Goal
Part H requires **raw (unadjusted)** prices. Yahoo describes its historical "Close" as adjusted for splits, and "Adj Close" as adjusted for splits and dividends. yfinance's `auto_adjust=False` therefore **doesn't prove** anything about the values.

This task:
1. **Determines from evidence what each field actually means**, separately for:
   - daily prices, daily volume, hourly prices and hourly volume;
   - dividend amounts and split ratios.
2. **Chooses each field's transformation from that evidence.** There's no single hypothesis that everything must satisfy.
3. Documents the evidence and the precision limits.
4. **Only for fields whose semantics are established**, imports NVDA's splits and dividends as CorporateActions.

Reconstructed values can satisfy Part H's "unadjusted" requirement when the reconstruction is independently verified (accepted in Codex review).

## The complete split history
Every reconstruction uses `F(d)`: the product of split ratios with `d < ex_date <= download date`. **All** splits after `d` count, including splits after the requested window. Rules:
- **Full history only.** yfinance's `history(start, end, actions=True)` reports only events inside the requested dates, so it must **never** be the source of `F`. The split history comes from a **full-history** request (e.g. `Ticker.splits`, or `history(period="max", actions=True)`). The task records which call is used, and the integration check confirms that the call isn't date-filtered.
- **Same adjustment basis.** Within one import run, the split history is fetched **immediately before and after** the data download. If the two differ (a split landed mid-run), the run aborts.
- **Completeness is checked** against the cited split list (evidence S below) for every date the import covers.
- **Agreement with storage.** Before bars are imported (M1-13), the split history must equal the stored `yfinance` `SPLIT` actions (`actions_latest`, M1-11), or the import aborts.

## Field-by-field determination
Each field is decided **separately**. For each one, the result is one of:
- `UNADJUSTED`;
- `SPLIT_ADJUSTED_AS_OF_DOWNLOAD`;
- `OTHER` (e.g. dividend-adjusted);
- `UNDETERMINED`.

The transformation follows from the result:

| Result | Transformation | Stored basis |
|---|---|---|
| `UNADJUSTED` | identity | `RAW_AS_REPORTED` / `AS_REPORTED` |
| `SPLIT_ADJUSTED_AS_OF_DOWNLOAD` | split reconstruction (below) | `RAW_RECONSTRUCTED_FROM_SPLIT_ADJUSTED` / `RECONSTRUCTED_FROM_SPLIT_ADJUSTED` |
| `UNDETERMINED`, but **primary evidence** shows the field is at most split-adjusted (e.g. not dividend-adjusted), and it's consistent with the daily data | identity **only where `F(d) == 1`** (no split between bar and download, so the value is the same either way) | `RAW_NO_LATER_SPLIT` / `NO_LATER_SPLIT` |
| `OTHER`, or `UNDETERMINED` otherwise | **none: the field is blocked** | — |

**Reconstruction** (only for `SPLIT_ADJUSTED_AS_OF_DOWNLOAD` fields):
```
price(d)    = vendor_price(d) × F(d)       → quantize PRICE_QUANTUM, half-even
volume(d)   = vendor_volume(d) ÷ F(d)      → quantize SHARE_QUANTUM
dividend(e) = vendor_dividend(e) × F(e)    → quantize PRICE_QUANTUM
```
Using splits that happened *after* d is **not look-ahead**: it undoes the vendor's later adjustment to recover values actually traded on d.

### Evidence for each field
Independent references are recorded in `nvda_reference.json`. Each has its source, citation and retrieval date, and **none is written from memory**.

| Code | Field | Evidence required | Decision rule |
|---|---|---|---|
| **S** | Split ratios and ex-dates | Company split announcements (cited) for every split in the covered range. The 2021-07-20 4:1 and 2024-06-10 10:1 splits are to be confirmed from those citations. | Vendor ratio and ex-date equal the cited ones; otherwise blocked |
| **P-D** | Daily OHLC | (1) At least one **cited as-traded close per split epoch** (before, between and after the splits in range). (2) Supporting: whether the vendor series shows a step of about the ratio at each ex-date. (3) Close compared with Adj Close around dividend ex-dates. | Pick the semantics under which **all** anchors match within tolerance. If both or neither match, it's `UNDETERMINED`. If Close follows Adj Close's dividend steps, it's `OTHER`. |
| **V-D** | Daily volume | **Primary evidence (one is required):**<br>(a) independently cited as-traded share volumes for sessions **before** a split in range, where the two candidates differ;<br>(b) reliable **provider documentation** stating explicitly whether volume is split-adjusted, quoted with link and retrieval date. yfinance's own documentation counts only for yfinance's processing, not for Yahoo's data.<br>**Supporting only:** dollar-volume continuity across each split (median price × volume over 20 sessions each side). Recorded, but **it never decides**; see the counterexample below. A volume jump alone proves nothing. | **Established only by primary evidence:** (a) anchors within tolerance under exactly one candidate, or (b) an explicit documented statement.<br>If primary and supporting evidence disagree, record it and investigate.<br>**Without primary evidence, the result is `UNDETERMINED` and the field is `BLOCKED`.** That includes the `F == 1` exception, which also needs primary evidence (table above).<br>If primary evidence shows volume is unadjusted, identity is correct, even when prices are reconstructed. |
| **P-H** | Hourly OHLC | (1) **Consistency with daily** on overlapping sessions: the hourly high and low equal the daily high and low within tolerance; first open and last close are compared and differences recorded. (2) If any split ex-date falls inside hourly coverage, the P-D method applied to hourly data. | If (2) is possible, decide as for P-D. If not (no split within hourly coverage), the result is `UNDETERMINED` but consistent: identity is allowed only where `F(d) == 1`. |
| **V-H** | Hourly volume | **Primary evidence** as for V-D: cited as-traded hourly or daily volumes that bear on the hourly basis, or explicit provider documentation for intraday volume.<br>**Supporting only:** the sum of hourly volume compared with daily volume on overlapping sessions (ratio distribution recorded), and dollar-volume continuity if a split falls inside coverage. | As for V-D: established only by primary evidence; otherwise `UNDETERMINED` and `BLOCKED` |
| **D** | Dividend amounts | Company-declared per-share amounts (cited) for dividends in the covered range | `UNADJUSTED` if vendor = declared; `SPLIT_ADJUSTED_AS_OF_DOWNLOAD` if vendor × F = declared; otherwise `UNDETERMINED`. Where `F == 1` the two agree, so only dividends **before** a split are decisive. |

**Tolerances:**
- prices: within **$0.01** of an anchor;
- dividends: **exactly equal** after quantization;
- volume anchors: within **0.5%**, because published volumes differ by venue coverage.

The maximum observed error per field is recorded.

### Why dollar-volume continuity can't decide (counterexample)
Consider a 4:1 split, with real trading activity rising around it:

| | Before split | After split |
|---|---|---|
| As-traded price | 40 | 10 |
| As-traded volume (the truth) | 1,000 | 16,000 |
| Vendor volume (split-adjusted: before × 4) | 4,000 | 16,000 |

Testing the two candidates, with prices reconstructed to as-traded:
- **"Vendor volume is unadjusted" (identity):** dollar volume 40 × 4,000 = 160,000 before, and 10 × 16,000 = 160,000 after. **Ratio 1.0, so it looks perfectly continuous.**
- **"Vendor volume is split-adjusted" (reconstruct ÷ 4):** 40 × 1,000 = 40,000 before, and 160,000 after. Ratio 4.0.

The heuristic favours identity and would store **4,000 shares where 1,000 were traded**. Genuine changes in activity around a split (common, since splits often follow strong price moves) look exactly like an adjustment. Hence the rule: **continuity is supporting evidence only**, and a cited anchor of 1,000 shares, or explicit documentation, is what establishes the basis.

### Precision limits (documented, not hidden)
The provenance document records, per field:
- the vendor's delivered precision (observed decimal digits, and the float representation);
- the resulting bound on reconstruction error (≈ `F × vendor rounding unit`);
- the measured maximum error against anchors;
- a statement of which stored digits are significant.

The stored quantum (`0.0001`) can be **finer than the information** in a reconstructed value. The report (M1-17) points to this note.

Importers (this task and M1-13) call `transformation_for` for **each field** they write. `IDENTITY_IF_NO_LATER_SPLIT` obliges the caller to check `split_factor(...) == 1` for every record, and to reject any record where it isn't.

### Corporate-action import
```python
def import_actions(instrument_id: str, *, clock: Clock, resolver: SqliteSymbolResolver,
                   writer: MarketDataWriter, fetch=<yfinance full-history fetch>) -> WriteResult
```
- The symbol comes from SymbolMapping (`provider = "yfinance"`); the ticker is never hard-coded.
- The **full** split and dividend history is fetched, bracketed by the before-and-after split-history check.
- `SPLIT` requires `SPLIT_RATIO` to be verified. It's stored with `ratio = Decimal(str(vendor_ratio))`, `source = "yfinance"`.
- `DIVIDEND` uses the `DIVIDEND_AMOUNT` transformation, with `F(e)` computed from the complete split history.
- `received_at` is `clock.now()` when the download completes. First-seen actions are `BACKFILL_ASSUMED`, available from the start of the ex-date. Later changes become `OBSERVED` revisions through the writer.

### Provenance document (`docs/data-provenance/yfinance.md`)
It records:
- yfinance version, every request call and its parameters (including the full-history split call), and retrieval times (UTC);
- Yahoo's own field definitions, quoted with link and retrieval date;
- the evidence and decision for each field, with every anchor's citation;
- the formulas, tolerances, precision limits and maximum errors;
- the stored basis labels;
- known limitations.

## If verification blocks
A field that ends `OTHER` or `UNDETERMINED`, outside the `F == 1` case, is **blocked**:
1. **Investigate first.** Look for more anchors, other yfinance call options, or the hourly/daily relationship. A failed initial expectation isn't, by itself, a reason to change the architecture.
2. While a field is blocked, **every task that writes it is blocked**:
   - a blocked `DIVIDEND_AMOUNT` blocks this task's dividend import;
   - a blocked D1 or H1 field blocks the matching part of M1-13 and of the M1-17 import command;
   - and in every case, **M1 completion** is blocked.
3. **Only if** investigation shows this source can't meet the raw-value requirement, a **proposed ADR** is written (e.g. an alternative data source, or an explicit adjusted-basis contract). It isn't adopted without review and acceptance. **A proposal alone doesn't unblock anything.** The blocked work resumes only after an accepted ADR, the matching updates to the architecture and specs, and their implementation.

## Implementation choices
**Resolved**
- **Fixtures are recorded once** by `integration` tests and stored with metadata (version, call, parameters, retrieval time). Unit tests use only fixtures; the existing network guard stays on.
- **Anchors must be independent of Yahoo:** company announcements, or a dated publication of an as-traded value. Many free historical sources are themselves split-adjusted and don't qualify.
- `repair=False` and `back_adjust=False`, so yfinance doesn't silently alter data.

**Unresolved**
- **Which sources count as acceptable anchors** for as-traded closes and volumes (Codex and owner, at spec review).
- **The determination results**, which aren't known until this task runs.

## Acceptance tests
**Split factor:**
- around each ex-date;
- a bar dated **years before** the window end still receives every later split up to the download date;
- a request window that excludes a later split doesn't change `F`.

**Split-history checks:**
- a date-filtered split list (missing a later split) is detected as incomplete;
- a before/after mismatch aborts the run.

**Field determination on fixtures:**
- each field's decision matches `YAHOO_VERIFICATION`;
- synthetic cases cover each outcome:
  - unadjusted volume **established by a cited anchor**, with adjusted prices (identity chosen for volume);
  - a dividend-adjusted Close (`OTHER`, blocked);
  - volume with **no primary evidence** (`UNDETERMINED`, `BLOCKED`, including rows where `F == 1`).

**Volume counterexample (Codex finding):** the 4:1 case above, as a synthetic fixture.
- With **only** the continuity test as evidence, the determination is `UNDETERMINED` / `BLOCKED`, and it is **never** `IDENTITY`, even though continuity favours identity (ratio 1.0).
- With a cited anchor of 1,000 shares added, the determination is `SPLIT_ADJUSTED_AS_OF_DOWNLOAD`, and reconstruction yields 1,000.
- With an anchor of 4,000 shares instead, it's `UNADJUSTED`.
- Each case also checks that the supporting continuity result is recorded but has no effect on the decision.

**`transformation_for`:**
- raises for a blocked field or a different yfinance version;
- `IDENTITY_IF_NO_LATER_SPLIT` records with `F > 1` are rejected by the importer.

**Import:**
- importing the fixture gives the cited splits and the declared dividend amounts;
- a second import adds nothing;
- one changed dividend gives an `OBSERVED` revision 2, available from its observation time.

**Live check (`integration`, not run by default):**
- the full-history split call returns splits outside any requested window;
- the live columns match the fixtures.
