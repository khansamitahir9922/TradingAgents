## Goal
Implement the `Candle` contract from Part H, with:
- `FORMING` and `CLOSED` states (Law 7);
- Decimal OHLC values (ADR-007);
- revisions (Law 8, ADR-009);
- three things M1 needs:
  - **which provider** the record came from, as part of its identity;
  - **how each field was obtained** (price basis and volume basis, set separately);
  - **when the record may be seen in replay** (availability).

The availability types are shared with corporate actions (M1-09).

## Contracts
```python
# availability.py
class AvailabilityBasis(StrEnum):
    OBSERVED          # available_from == received_at: we saw it at that time
    BACKFILL_ASSUMED  # first seen in a historical download; available_from is an assumption

PROVIDER_ID_PATTERN = r"^[a-z][a-z0-9_]*$"   # e.g. "yfinance"; same values as SymbolMapping.provider

# candles.py
class Timeframe(StrEnum): D1, H1
class BarState(StrEnum): FORMING, CLOSED
class PriceBasis(StrEnum):
    RAW_AS_REPORTED                        # the provider's values are verified as-traded (unadjusted)
    RAW_RECONSTRUCTED_FROM_SPLIT_ADJUSTED  # as-traded values rebuilt by a verified split reconstruction
    RAW_NO_LATER_SPLIT                     # provider values used unchanged because no split occurred between
                                           # the bar and the download, so split adjustment can't have changed them
class VolumeBasis(StrEnum):                # the same three meanings, for share volume
    RAW_AS_REPORTED
    RAW_RECONSTRUCTED_FROM_SPLIT_ADJUSTED
    RAW_NO_LATER_SPLIT

@dataclass(frozen=True)
class Candle:
    source: str                 # the PROVIDER id (PROVIDER_ID_PATTERN); part of the record identity
    instrument_id: str
    timeframe: Timeframe
    start_time: datetime        # UTC
    end_time: datetime          # UTC
    open: Decimal; high: Decimal; low: Decimal; close: Decimal   # quantum PRICE_QUANTUM
    currency: str
    volume: Decimal             # shares, quantum SHARE_QUANTUM
    state: BarState
    source_version: str         # e.g. the yfinance version
    price_basis: PriceBasis
    volume_basis: VolumeBasis
    import_id: str
    event_time: datetime        # UTC; == end_time for a CLOSED bar (Law 5)
    received_at: datetime       # UTC; when THIS SYSTEM received this revision (observation time)
    processed_at: datetime      # UTC
    revision: int               # >= 1, numbered per identity
    available_from: datetime    # UTC; earliest replay time at which this revision may be seen
    availability_basis: AvailabilityBasis

    @property
    def identity(self) -> tuple[str, str, Timeframe, datetime]:
        return (self.source, self.instrument_id, self.timeframe, self.start_time)
```

## Rules enforced by the contract
1. All datetimes are aware UTC, and `start_time < end_time`.
2. Prices are > 0, with `low <= min(open, close) <= max(open, close) <= high`. Volume is ≥ 0.
3. Values must already be at their quantum. The contract **rejects** extra precision; it never rounds silently.
4. `available_from >= event_time`: nothing is available before it happened.
5. `OBSERVED` ⇒ `available_from == received_at`.
6. **`revision >= 2` ⇒ `OBSERVED`.** A later revision is never backdated.
7. `BACKFILL_ASSUMED` ⇒ `revision == 1`.
8. `CLOSED` ⇒ `event_time == end_time`. `FORMING` bars are allowed in memory but not stored (M1-10).
9. `source` matches `PROVIDER_ID_PATTERN`. Derived candles (M1-15) aren't `Candle`s with a provider source: they're wrapped in `ResampledBar` and can't be stored.

## Implementation choices
**Resolved**
- **The provider is part of the identity.** Records from different providers for the same instrument and bar never share revision numbering. One provider's value can't become another's "correction".
- **Price and volume bases are separate**, because a vendor may adjust one and not the other. M1-12 decides each from evidence.
- **Two kinds of time are kept apart:**
  - **observation** (`received_at`, never changed after storage);
  - **availability** (`available_from` with its basis).

  Simulated delivery times exist only in replay events (M1-14).
- **The added descriptive fields don't change the architecture** (accepted in Codex review): `currency`, `source_version`, `price_basis`, `volume_basis`, `import_id`, `available_from` and `availability_basis`. Part H lists key fields, and full schemas are written per milestone.

**Unresolved:** none.

## Acceptance tests
- Each rule (1–9) has a passing case and a failing case.
- A correction revision with `BACKFILL_ASSUMED` is rejected. A revision-2 record whose `available_from` differs from its `received_at` is rejected.
- A value with 5 decimal places is rejected, not rounded.
- `source = "resampled:yfinance"` (or any value not matching the pattern) is rejected.
- **Two providers:** candles from `yfinance` and `testvendor` for the same instrument and start time have different `identity` values.
- `Candle` is immutable.
