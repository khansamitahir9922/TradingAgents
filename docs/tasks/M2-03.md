## Goal
Freeze **everything a strategy may see at T** in one immutable object: feature values, the adjusted inputs' references, the DataHealth of the required sources, and the versions used. A strategy reads only the snapshot (Part F: Quant produces `FeatureSnapshot`).

## Allowed files
- `investment_engine/quant/snapshot.py` (new)
- `tests/engine/test_feature_snapshot.py` (new)
- `docs/tasks/M2-03.md`, `PROGRESS.md`

## Contracts
```python
@dataclass(frozen=True)
class FeatureSnapshot:
    instrument_id: str; source: str; as_of: datetime     # T, UTC
    session_date: date                                    # the latest closed session at T
    values: Mapping[str, float | None]                    # feature key -> value (None during warm-up)
    feature_versions: Mapping[str, str]                   # feature key -> version
    input_refs: tuple[BarRef, ...]                       # full identities of every raw bar used
    action_refs: tuple[ActionRef, ...]
    action_coverage: ActionCoverage
    unavailable_reason: str                            # adjustment unavailable, gap, or stale decision bar
    adjusted_basis: AdjustedBasis
    data_health: DataHealth                               # M1-16, at the same T

def build_snapshot(instrument_id: str, source: str, features: Sequence[FeatureDefinition], *,
                   at: datetime, reader, calendar, health: DataHealth,
                   coverage: ActionCoverage) -> FeatureSnapshot
```

## Rules
1. **One T for everything:** bars, actions, features and DataHealth are all as of the same `at`. `health.as_of` must equal `at`, or the function raises.
2. **Immutable:** mappings are read-only.
3. **References are complete:** every raw bar any feature used is listed with its revision.
4. **Missing data isn't hidden:** a feature in warm-up is `None`. DataHealth is carried as given; the abstention decision is M2-06's.
5. Validate `health.instrument_id`, provider/required timeframe coverage and T against the request. Features use calendar-consecutive closed sessions ending at the latest expected close at T. A hole anywhere in a feature's required window, or a missing latest decision bar, marks the snapshot unavailable even if M1's shorter health lookback reports OK. Warm-up from the verified history boundary is labelled separately from a missing interior session. RSI uses its entire declared seed-to-T history, whose references are included. Read extra historical bars only within verified coverage.
6. Catch only the specific `AdjustmentUnavailable` condition to produce an unavailable snapshot. Programming errors, malformed data and database errors propagate. Availability is never guessed from an empty action query.

## Implementation choices
**Resolved — persistence:** the snapshot isn't persisted on its own. Its references go into the `LineageRecord` (M2-07). This answers M1-16's open item: the DataHealth used for a view is recorded with that view's lineage.
**Unresolved:** none.

## Acceptance tests
- Same inputs and T give an identical snapshot; a later T with a correction differs only where the correction applies.
- A mismatched `health.as_of` raises.
- `input_refs` covers exactly the bars used (checked against a hand-built window).
- Mappings are immutable.
- Mismatched instrument/health or incomplete health entries raise; a missing session older than the 20-session health window is detected in a 200-session feature window. Missing latest bar does not recycle yesterday's signal. Unavailable action coverage yields an explicit reason and no fabricated feature values.
