## Contracts

The [M6 shared contracts](M6-README.md#shared-contracts) govern this task.

1. `ResearchPort.run(job, *, clock) -> RunOutput` builds `TradingAgentsGraph` from the job's frozen settings (pinned models, `llm_max_retries=0`, checkpointing off, results directory under the worker's data dir) and the M6-00 callback.
2. Capture: every LLM call's messages and response, every tool call/result, data-vendor/endpoint/fetched_at references, final state (reports, structured objects from M6-03), upstream version and repository code version, warnings, usage.
3. Ticker comes from the existing SymbolMapping for the instrument; the run date must equal the current exchange date (D50) or the job is refused before any LLM call.
4. Exceptions are captured as outcome FAILED with type and sanitized message; secrets are never captured (prompts are scanned for the loaded key and redacted, with a test).

## Implementation/check record

It captures every prompt, response, tool input and tool output (verbatim untrusted text, cut beyond 1,000,000 characters with the cut recorded), the selected final state including the U1 structured objects, the upstream and repository versions and usage. ## Implementation/check record

Codex review B5 (`llm_max_retries=0` did not stop upstream's application-level retry), fixed, adapter-local, with no upstream change. A `ProviderFailureGuard` callback, placed first among the run's handlers, records the provider's first error and refuses every later model call in its start callback, before the request is sent. Upstream's structured-to-free-text fallback therefore cannot make a second paid call after a quota/429 error, and a run in which the provider failed is recorded FAILED with no context, even when upstream swallowed the error and carried on. Malformed or unsupported structured output is a parser path, not a provider error, so upstream's free-text fallback for it is unchanged (tested). The failure text now reads "provider error: <type>: <redacted message>; no further model calls were made"; one older assertion on its prefix was relaxed to the type.

## Implementation/check record

Codex review B2 (redaction missed upstream files and logs, escaped and short secrets), fixed. The `Redactor` is now one regular-expression pass over every nonempty configured secret and its JSON-escaped forms (with and without ASCII escaping), longest first, so a replacement marker can never be re-matched, and serialized text with quotes, backslashes or Unicode is covered. `deep()` redacts plain JSON-like data. The adapter hands upstream's `record_decision` (its state-log file and memory-log entry) the deep-redacted state, never the raw one, and during a run installs a log-record factory that redacts every record's message and formatted exception before any handler sees it. That covers upstream's structured-call warning that printed the exception text. The secrets loader refuses values shorter than 8 characters as too short to redact safely.

The first leak tests passed vacuously, because my scripted model never quoted tool output and the failing model didn't fail in a structured call; both scenarios were strengthened (an echoing model, a quota error carrying the secret on the Trader's structured call) and then reproduced every leak before the fix: the secret appeared in upstream's results JSON and memory log, and in its log warning.
