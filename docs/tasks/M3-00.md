## Goal
Make a local PostgreSQL usable by the code and the tests, with no secret in the repository and tests confined to the local machine (ADR-008).

## Allowed files
- `pyproject.toml`: the `engine` and `dev` optional-dependency lists (add `psycopg[binary]`), and the `[tool.pytest.ini_options]` markers (register `postgres`)
- `.github/workflows/ci.yml`: the test job only: a `postgres` service container and the test DSN environment variable
- `tests/conftest.py`: the `_no_network` fixture only (see rule 4)
- `tests/engine/conftest.py`: a `pg_database` fixture
- `tests/engine/test_postgres_harness.py` (new)
- `tests/engine/test_layering.py`: one new rule (rule 5)
- `docs/dev/postgresql.md` (new), `docs/tasks/M3-00.md`, `PROGRESS.md`

## Contracts
```python
# tests/engine/conftest.py
@pytest.fixture
def pg_database() -> Iterator[str]:
    """A fresh, empty database for one test; yields its DSN; dropped afterwards."""
```
Environment variable `INVESTMENT_ENGINE_TEST_PG_DSN`: a DSN for a maintenance database on a loopback host whose role may `CREATE DATABASE`.

## Rules
1. **Driver.** `psycopg` 3 with its binary wheel. Before declaring it, verify that wheels exist for Python 3.11–3.14 on Windows and Linux, as M1-10 did for `pyarrow` and `duckdb`, and record the installed version and the evidence in PROGRESS. The lower bound is the verified version. psycopg is imported only under `investment_engine/storage/` and in tests, never at package import time.
2. **No secrets in the repository.** The DSN comes only from the environment. It's never printed, logged, put in an exception message or written to a file; errors name the variable, not its value. `docs/dev/postgresql.md` explains the PostgreSQL 17 Windows installer, `listen_addresses = 'localhost'`, a dedicated role with `CREATEDB` (not a superuser), and keeping its password in a Windows user environment variable or `pgpass.conf`, never in `.env` or the repository.
3. **Isolation.** Each `postgres` test gets a new database named `ie_test_<random hex>`, created from `template0` and dropped afterwards, even when the test fails. Tests never touch the maintenance database's tables or any other database.
4. **Local only.** libpq connects without Python sockets, so today's socket guard doesn't stop it. `_no_network` gains two parts. Tests not marked `postgres` or `integration` can't open a psycopg connection (it raises like the socket guard). `postgres` tests may connect only when the DSN's host is `localhost`, `127.0.0.1` or `::1`, or a local socket. Any other host fails the test before connecting. The existing socket and HTTP guards are unchanged.
5. **Layering rule** in `test_layering.py`: `psycopg` is imported only under `investment_engine/storage/`.
6. **Skips must be visible.** Without `INVESTMENT_ENGINE_TEST_PG_DSN`, `postgres` tests skip with the reason "PostgreSQL test DSN not set (see docs/dev/postgresql.md)". From this task on, a task or batch check passes only if the run reports **zero** skipped `postgres` tests. The check commands are recorded in PROGRESS with the count.
7. **CI.** The test job runs a `postgres:17` service on localhost with a throwaway password defined in the workflow (it guards a disposable CI database, not a real secret) and sets `INVESTMENT_ENGINE_TEST_PG_DSN`. CI runs only when the owner pushes; until then report "CI not yet run".

## Implementation choices
Resolved: psycopg 3 is PostgreSQL's maintained Python driver, and its binary wheel needs no compiler. Resolved: a database per test keeps tests independent at the cost of speed. If the suite becomes too slow, a later reviewed change may switch to one database per session with transactions rolled back.
Unresolved: D16 (owner). Until PostgreSQL is installed, this task stops at its checkpoint and reports.

## Acceptance tests
- `pg_database` creates a database that exists during the test, is empty, and is gone afterwards; also after a failing test (exercised via a nested pytest run).
- A non-loopback DSN host makes a `postgres` test fail before any connection attempt; a test without the marker can't connect.
- Without the DSN the tests skip with the documented reason; the error and skip messages never contain the DSN value (a fake DSN with a recognisable password is checked against all output).
- The layering rule finds no psycopg import outside `investment_engine/storage/`.
- Clean-install smoke: the `engine` extra installs `psycopg` from a wheel in a fresh venv.
