# M2-01: Versioned feature definitions and the float64 boundary

## Goal
Every feature a strategy uses has a **name, a version and a declared input**, so that a view can be traced to the exact computation (Part F: Quant owns "feature definitions (versioned)"). Quant code works in float64 (ADR-007). Decimal values cross into it only through the M1-02 converters.

## Allowed files
- `investment_engine/quant/features.py` (new)
- `tests/engine/test_features.py` (new)
- `docs/tasks/M2-01.md`, `PROGRESS.md`

## Contracts
```python
@dataclass(frozen=True)
class FeatureDefinition:
    name: str                    # e.g. "sma"
    version: str                 # semantic version; bumped on any change to the computation
    params: Mapping[str, int | float]   # e.g. {"window": 200}; frozen
    input_basis: AdjustedBasis   # which M2-00 series it reads
    warmup_sessions: int         # sessions needed before a value exists
    key: str                     # derived: f"{name}@{version}{sorted params}", unique

class FeatureRegistry:
    def register(self, definition: FeatureDefinition) -> None   # identical registration is a no-op; conflicting definition raises
    def get(self, key: str) -> FeatureDefinition
```

## Rules
1. **A definition is immutable.** A different computation needs a new `version`. Registering a different definition under an existing key raises.
2. **Warm-up is declared.** A feature has **no value** until `warmup_sessions` input sessions exist. It's never back-filled with partial windows.
3. **Float64 only inside Quant.** Inputs arrive as `AdjustedBar` floats (M2-00). Decimal never enters a feature computation directly.
4. Parameters are deeply immutable, finite, canonicalized and validated against each feature's declared parameter schema. Booleans are not window sizes. Keys use canonical serialization, not a Python repr; name/version/parameters/input basis all participate. Feature definitions do not accept executable text or vendor data as code.

## Implementation choices
**Resolved:** params are part of the key, so `sma(window=50)` and `sma(window=200)` are different features.
**Unresolved:** none.

## Acceptance tests
- Registering the same definition twice is idempotent; a changed computation under the same key raises.
- Keys are unique and deterministic, whatever the parameter order.
- A Decimal passed where a float is required raises (the boundary is explicit).
- `warmup_sessions` is required and positive.

## Out of scope
The indicators themselves (M2-02); ML features (M9).
