## Goal
Decide deterministically whether an allowed intent version is within limits, and if it's too big, reduce it, where a reduction is a new version, never an edit (G1 step 8; Laws 3 and 12; ADR-004 §2).

## Allowed files
- `investment_engine/risk/checks.py` (new); `investment_engine/risk/decisions.py` (helpers only, contract unchanged)
- `tests/engine/test_risk_checks.py` (new)
- `docs/tasks/M3-11.md`, `PROGRESS.md`

## Contracts
```python
@dataclass(frozen=True)
class RiskInputs:
    snapshot: PortfolioSnapshot; limits: RiskLimits; halt: Halt | None
    adv: Decimal | None; adv_refs: tuple[BarRef, ...]      # D4: mean raw close x volume of the last N completed D1 bars
    new_buys_this_session: int    # D5: this account's BUY intents for the same target session that reached
                                  # AWAITING_APPROVAL or APPROVED (later expiry or decline doesn't free a slot)
    view: MarketView; view_lineage: LineageRecord

def check_risk(intent: OrderIntent, inputs: RiskInputs, *, at: datetime) -> tuple[RiskDecision, HaltRequest | None]
def reduced_version(intent: OrderIntent, decision: RiskDecision, *, at: datetime) -> OrderIntent   # version + 1
```

## Rules
1. **Checks, in order, all reported:**
   1. `fresh_data`: the view isn't ABSTAIN, `at < view.valid_until` (D10), its required sources were OK, and the reference bar is the view's decision bar.
   2. `halt`: an active halt rejects BUYs ("drawdown halt since <time>"); SELLs pass.
   3. `drawdown` (D3): if equity <= peak × (1 - `drawdown_halt_fraction`), a BUY is rejected and a `HaltRequest` is returned. The pipeline records the latched halt (M3-06).
   4. `min_price` (D6): a BUY below `min_price` is rejected.
   5. `position` (D1): post-trade position value at the limit price must be <= `max_position_fraction` × equity.
   6. `cash` (D2): a BUY's cost at the limit price must be <= cash (no borrowing). Gross exposure after the trade must be <= `max_gross_exposure_fraction` × equity.
   7. `liquidity` (D4): quantity × reference price must be <= `max_order_adv_fraction` × ADV. A missing or short volume history rejects ("volume history unavailable"), never assumes.
   8. `daily_buys` (D5): a BUY is rejected when `new_buys_this_session` >= the limit. The count is in the reason, for reconstruction.
2. **Outcome.** Any failure of checks 1–4 or 8 is REJECT. Failures of only 5, 6 or 7 are REDUCE to the largest whole-share quantity that satisfies all three. If that's below `min_quantity` (D9), the outcome is REJECT. Otherwise APPROVE.
3. **Reduction = new version** (Law 12). `reduced_version` copies every field except `quantity` and `version`, sets `supersedes` to the old version, and keeps the same id. The pipeline marks the old version SUPERSEDED and runs policy and risk again on the new one. A second REDUCE on a reduced version is a defect: it's rejected as "reduction did not converge" and logged.
4. **Deterministic and Decimal.** No store or clock reads inside `check_risk`; the same inputs give the same decision. All arithmetic is Decimal with a fresh context. Comparisons at exactly the limit pass.
5. Reasons show numbers in the decision's currency and the limit version, e.g. "position 12.4% > 10% (risk-1): reduce 80 -> 64".

## Acceptance tests
- Each check failing alone, with hand-calculated numbers; exactly-at-limit passes.
- REDUCE when several reducible checks fail: the minimum of the three allowed quantities; below one share becomes REJECT.
- `reduced_version` keeps the id and all material fields except quantity; the re-check of the new version APPROVEs; a forced second reduction gives REJECT with the defect reason.
- Halt: an active halt rejects BUYs and passes SELLs; a drawdown at the threshold returns a HaltRequest.
- Missing ADV, ABSTAIN, an expired view and an unhealthy view each REJECT with their reasons.
- Same inputs give equal decisions; no float in any quantity, price or comparison.

## Out of scope
Sector concentration (no sector data), volatility or VaR limits, intraday risk, the M4 gate's "still current" re-check.
