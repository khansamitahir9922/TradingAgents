## Contracts

The [M6 shared contracts](M6-README.md#shared-contracts) govern this task.

1. ResearchJob, job-state versions with CAS, ResearchRecord, ResearchContext, BudgetPolicy, BudgetUsage as in C1; deterministic IDs exclude live command time where they identify business content, and keep it as provenance.
2. Validation: instrument via existing InstrumentId checks; aware UTC; Decimal money; PortfolioRating/TraderAction mirrored as platform enums (no import of upstream types into contracts).
3. `suggested_levels` is a typed `UntrustedLevels` with Decimal-or-None values and a fixed label; it has no conversion to any order/limit type.
4. Adding `ProcessRole.RESEARCH` changes no existing order-state edge or ownership (existing tests prove it).

## Implementation choices

- Owner decisions D45-D54 govern; do not silently choose differently. Until accepted, this is a draft.
- No new process beyond the architecture's Research Worker, no broker capability, no change to MarketView, sizing, policy, risk, gate, OMS or ledger behaviour.
- Injected clocks only; Decimal for money; aware UTC times; untrusted text stays untrusted (Law 4).
- A spec gap needing an architecture/ADR change, a file outside the allowed list, or a new test failure stops the package.

## Acceptance tests

- Round-trip through the lineage codec; old records' IDs unchanged.
- Floats, naive times, unknown ratings and overlong text are refused with typed errors; unknown tokens stay unknown.
- `valid_until` before `generated_at` refused.
