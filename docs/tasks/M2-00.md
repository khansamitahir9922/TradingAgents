## Goal
Indicators and returns need prices on one basis across splits. Without that, NVDA's 10-for-1 split on 2024-06-10 looks like a 90% crash. Stored prices stay **raw** (Part H; ADR-009). This task derives a **split-adjusted view as of a time T**, from stored raw daily bars and stored `SPLIT` actions, **using only what was available at T**.

This is the agreed "adjusted view first" item from the reviewed ML proposals (PROGRESS, "Reviewed ML proposals", item 1).

## Contracts
```python
class AdjustedBasis(StrEnum):
    SPLIT_ADJUSTED_AS_OF = "SPLIT_ADJUSTED_AS_OF"      # price return only

class AdjustmentUnavailable(ValueError):
    """Declared coverage or an adjustment input is unavailable; the policy must abstain."""

@dataclass(frozen=True)
class AdjustedBar:                       # quant domain: float64 (ADR-007), never stored, never a Candle
    source: str; instrument_id: str; session_date: date
    open: float; high: float; low: float; close: float; volume: float
    basis: AdjustedBasis
    as_of: datetime                      # T
    factor: Decimal                      # cumulative split factor applied (exact)
    raw_ref: BarRef                      # full identity, revision, import_id and availability labels
    action_refs: tuple[ActionRef, ...]   # every split revision used

@dataclass(frozen=True)
class BarRef:
    source: str; instrument_id: str; timeframe: Timeframe; start_time: datetime
    revision: int; import_id: str; available_from: datetime
    availability_basis: AvailabilityBasis

@dataclass(frozen=True)
class ActionRef:
    source: str; instrument_id: str; action_type: ActionType; ex_date: date
    revision: int; import_id: str; available_from: datetime
    availability_basis: AvailabilityBasis

@dataclass(frozen=True)
class ActionCoverage:
    source: str; instrument_id: str; types: tuple[ActionType, ...]
    first: date; last: date; as_of: datetime
    established: bool; evidence_refs: tuple[str, ...]; reason: str

def adjusted_daily(reader, source: str, instrument_id: str, first: date, last: date, *,
                   at: datetime, calendar, coverage: ActionCoverage,
                   basis: AdjustedBasis = AdjustedBasis.SPLIT_ADJUSTED_AS_OF
                   ) -> list[AdjustedBar]
```

## Rules
1. **Point in time.**
   - Raw bars are read with `candles_visible_at(source, …, D1, …, at)`.
   - Splits are read with `actions_visible_at(source, …, at, types={SPLIT})`.
   - A split counts only if its revision is **available by T** and its **ex-date is on or before T's session date**.
   - A correction observed after T never changes a view computed at T.
2. **Factor.** For a bar on session `d`, `F_T(d)` is the product of the ratios of the counted splits with `d < ex_date`. Prices are divided by `F_T(d)`, and volume is multiplied by it. The arithmetic is exact Decimal; conversion to float64 happens once, through `money.to_float64`. The result: the latest bars are as traded at T, and earlier ones are scaled down to them.
3. **Adjustment range and coverage.** Read actions from the first requested session through T's local date, including splits after the last requested bar. An empty action result proves no coverage by itself. Require established `ActionCoverage` for the same provider, instrument, SPLIT type, T and whole range; otherwise raise `AdjustmentUnavailable` so the policy can abstain. Coverage evidence is an explicit, versioned research assumption based on the verified import record; it is not a claim of historical observation. A covered range with zero splits is valid. Future announced splits are excluded until effective. Validate returned identities, currency, raw price/volume bases, CLOSED state, session boundaries and availability. Reject non-finite converted outputs.
   - **Zero-split evidence:** each evidence reference must identify completed verification establishing exhaustive coverage for the exact provider, instrument, SPLIT type, date range and `as_of`, including request bounds and the verification version. An empty local query, missing or partial page, or failed import is not evidence of zero splits and leaves coverage unestablished. A completed verification may establish zero events; its references must survive into M2-07 lineage alongside the input revisions.
4. **One provider.** Bars and actions come from the same `source`. Providers never mix.
5. **No filling.** A session with no visible bar is absent from the output. M1-16 checks its lookback; M2-03 also checks the full declared feature window. Neither may impute a missing session.
6. **Not stored, not a Candle.** Adjusted bars can't be written by the store (M1-08 rule 9).
7. **Completed bars only** (Codex package review, correction 5). Every raw bar used must be `CLOSED`, with `end_time <= T` and `available_from <= T`; in a replay it must also have been delivered by T (M2-07 rule 5). A bar with `received_at < end_time` is refused as malformed, even though the M1-08 contract currently accepts it (a recorded M1 follow-up). Refusal raises; it never silently drops the bar.

## Implementation choices
**Resolved**
- **The adjustment is derived per call, as of T.** Two calls with different T can differ for the same historical day. That's correct, and it's why `as_of` and `factor` are carried.
- **Full references and coverage evidence** go into lineage (M2-07). Label BACKFILL_ASSUMED honestly; PIT querying doesn't prove the vendor was historically observed.
- **Total return is a separate labelled return/index contract in M2-08.** This task does not pretend that a simple dividend-adjusted OHLC series is the same object as a total-return calculation. Execution references, fills and accounting retain raw prices.

**Unresolved:** independent acceptance of the coverage-evidence contract. This spec defines no new authoritative store; coverage is a versioned input to Quant and lineage.

## Acceptance tests
- **The NVDA 2024 split:**
  - with T after 2024-06-10, bars before the ex-date are divided by 10, and the closes on 2024-06-07 and 2024-06-10 are continuous within the day's real move;
  - with T on 2024-06-07 (before the ex-date), no adjustment is applied.
- **Split visibility:** a split whose revision is available only after T isn't applied. A split correction, i.e. a changed ratio observed later, doesn't change the view at an earlier T.
- **Factor exactness:** with ratio 3 the factor is exact Decimal (no rounding until the single float conversion).
- **Providers:** a `testvendor` split never adjusts `yfinance` bars.
- **No filling:** a missing session stays missing.
- A split after the last requested bar but effective by T contributes to its factor; one effective after T does not.
- Missing/unestablished coverage raises; established coverage containing zero splits succeeds. Coverage from another provider, instrument, time or insufficient range is refused.
- Zero-split coverage without the completed verification references above is refused. Partial/failed-page evidence cannot establish zero splits; correctly scoped exhaustive verification with zero events succeeds and its references remain in lineage.
- Full bar/action references and backfill labels survive; stored file hashes remain identical before and after both successful and failed calls.
- **Never stored:** there's no write path; `AdjustedBar` isn't a `Candle`.
- **Completed bars only:** a FORMING bar, a bar with `end_time > T` and a bar with `received_at < end_time` are each refused.

## Out of scope
Intraday adjustment, total-return calculation (M2-08), symbol changes, other instruments (OPEN-05).
