## Goal
Decide deterministically whether an intent version is allowed at all: autonomy, promotion, instrument, restricted list, long-only and trading window (G1 step 7; Law 3).

## Allowed files
- `investment_engine/policy/checks.py` (new); `investment_engine/policy/decisions.py` (fill in helpers only, contract unchanged)
- `tests/engine/test_policy_checks.py` (new)
- `docs/tasks/M3-10.md`, `PROGRESS.md`

## Contracts
```python
def check_policy(intent: OrderIntent, *, account: Account, autonomy: AutonomySetting, rules: PolicyRules,
                 instrument: Instrument, snapshot: PortfolioSnapshot, view_lineage: LineageRecord,
                 calendar, at: datetime) -> PolicyDecision
```

## Rules
1. **Every check runs and is reported**, in this order, each with a plain reason; the decision passes only if all pass:
   1. `autonomy`: Level 0 fails "advisory account (Level 0): views only, no intents". Levels 1 and 2 pass and are recorded.
   2. `promotion` (D15, Law 19): a PAPER account fails "PROMOTION NOT ASSESSED: strategy versions <...> have no accepted promotion (OPEN-09)". No promotion registry exists in M3, so every PAPER intent fails here. A RESEARCH account passes with "research account: replay only; can never trade".
   3. `instrument`: ACTIVE and inside its active dates on `target_session`.
   4. `restricted`: not on the version's restricted list (D8).
   5. `long_only` (D2): a SELL can't exceed the shares held in the snapshot; a BUY is always long.
   6. `trading_window` (D7, D12): `target_session` is a regular session in the calendar (half-days allowed); order type LIMIT; TIF DAY; the view is D1.
2. **Deterministic.** Inputs are passed in, with no store or clock reads. The same inputs give an equal decision. `decided_at = at`.
3. **Missing inputs are prerequisites, not policy results** (Codex B3). `check_policy` is only called with every input present. A missing account, autonomy setting, rules or limits version, instrument, reference or snapshot is detected by the pipeline **before sizing**. It's recorded as a ProposalRecord `PREREQUISITE_MISSING` with the reason, and no intent and no decision exist (M3-12 rule 2). If `check_policy` is nevertheless given an inconsistent input (for example, an intent for another account), it raises; it never returns a pass or a fabricated failure.
4. **No LLM or external text** affects any check (Laws 3 and 4); reasons are fixed templates with values filled in.

## Acceptance tests
- One test per check failing alone, with its exact reason; all passing; several failing together (all reported).
- Level 0 on any account fails; PAPER fails promotion at Levels 1 and 2; RESEARCH passes promotion.
- Restricted list from an older version doesn't apply after a newer version removes the stock, and vice versa.
- A SELL larger than the holding fails `long_only`; a target session on a holiday or weekend fails `trading_window`.
- Same inputs give equal decisions; no clock read (the M1-01 checker covers the new module).
- Inconsistent inputs (another account's intent, an instrument mismatch) raise rather than decide.

## Out of scope
Risk limits (M3-11), the Pre-Execution Gate's re-check (M4), promotion thresholds (OPEN-09, owner).
