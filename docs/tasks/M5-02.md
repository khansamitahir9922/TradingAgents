## Contracts

The [M5 shared contracts](M5-README.md#shared-contracts) and accepted ADR-010 govern this task. Proposed rules for this task:

1. Implement activation/opening and fill-to-transaction plans in C2/C3. Cash-only start needs no lot cost; held opening shares require explicit OpeningLot quantities and costs matching the declared starting state.
2. BUY cash/notional/fee and share entries follow ADR-010. SELL uses the mandatory CostBasisPort plan; use a test double in this task and do not import the not-yet-built FIFO module. Missing plan is unavailable, never a zero cost.
3. Only accepted OMS fills can be selected. Match order/account/currency/source content against stored rows; preserve fill_id and broker_fill_id. Duplicate event delivery/source retry cannot repost.
4. Post each accepted partial or late fill, including accepted fills on CANCELLED/EXPIRED orders. Cancellation and other non-fill state changes create no economic posting. Refused/conflicting broker messages remain OMS anomalies.
5. Legacy activation is explicit and audited; enforce stored-operator Admin authorization at command_clock time inside the store transaction, not Actor.role. Never delete old snapshots or set history to synthetic current starting cash. Existing unknown/open orders keep reservations.
6. A known negative-cash outcome from an accepted fill is posted and flagged as a breach, not erased by the no-borrowing policy. Missing lot cost preserves the accepted-fill reference as a visible incomplete-book reason; never label the older book current.

## Acceptance tests

- Opening 100000, BUY 10 at 100 fee 1 gives cash 98999 and ten shares; reproduce exact journal directions.
- SELL with an explicit cost-400 plan gives the ADR cash/quantity example; missing cost refuses the entire batch.
- Repeated event, repeated broker fill and repeated activation do not double cash, shares or capital; changed content for a stored ID is refused.
- Accepted partial fills and a late cancelled-order fill post once each; rejected/conflicting messages and cancel requests post nothing.
- Nonzero initial position with missing/mismatched cost or quantity cannot activate; original account remains intact.
- Forged Admin Actor or deactivated operator cannot activate; an accepted fill causing negative cash remains recorded with a breach, while unknown basis is explicitly incomplete with its source reference.
