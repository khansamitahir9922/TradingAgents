## Goal
Give sizing and risk an exact, point-in-time view of an account's cash, positions, value and peak value (Part F Portfolio, Part H lineage "portfolio snapshot").

## Contracts
```python
class SnapshotSource(StrEnum):
    DECLARED_STARTING_STATE = "DECLARED_STARTING_STATE"   # M3: no ledger yet
    LEDGER = "LEDGER"                                     # reserved for M5; refused in M3

@dataclass(frozen=True)
class StartingState:
    account_id: str; effective_at: datetime; cash: Decimal; currency: str
    positions: tuple[tuple[str, Decimal], ...]    # (instrument_id, whole-share quantity); () by default (D14)
    declared_by: str; reason: str

@dataclass(frozen=True)
class PositionValue:
    instrument_id: str; quantity: Decimal
    reference_price: Decimal        # raw close of the latest CLOSED D1 bar available at as_of
    price_ref: BarRef; value: Decimal

@dataclass(frozen=True)
class PortfolioSnapshot:
    account_id: str; as_of: datetime; source: SnapshotSource; currency: str
    cash: Decimal; positions: tuple[PositionValue, ...]
    equity: Decimal                 # cash + sum of position values
    peak_equity: Decimal            # highest equity of this account's stored snapshots up to as_of, this one included
    starting_state_ref: str
    snapshot_id: str = field(init=False)   # "psn-" + SHA-256 of canonical content

def build_snapshot(account_id, *, at, starting: StartingState, reader, calendar, coverage,
                   history: Sequence[PortfolioSnapshot]) -> PortfolioSnapshot | SnapshotUnavailable
class PortfolioSnapshotStore:  # append-only; append(s), get(id), latest(account_id, at), history(account_id, at)
```

## Rules
1. **Declared, and labelled so.** In M3 the only source is the declared starting state (default: $100,000 cash, no positions, D14). Every display says DECLARED, not ledger-derived. The ledger replaces it in M5. Declaring a start is Admin-only and audited, and it's allowed once per account in M3 (a second declaration raises).
2. **Raw prices, point in time.** Positions are valued at the raw close of the latest CLOSED daily bar whose availability and delivery are at or before `as_of` (ADR-009; the M2 B2 cutoff). A missing or not-yet-available bar gives `SnapshotUnavailable` with its reason, never a stale or zero price.
3. **Corporate actions.** Quantities are as of `effective_at`. If verified coverage shows a split or dividend between `effective_at` and `as_of` for a held instrument, the snapshot is unavailable ("action since the declared start; ledger needed (M5)"). Missing coverage is also unavailable. Holding no positions needs no action coverage.
4. **Decimal throughout** (Law 16): values are quantity × price in Decimal, with a fresh context per calculation. No floats.
5. **Peak equity** is the maximum equity over this account's stored snapshots up to `as_of`, plus this one. With no history it's this snapshot's equity. Snapshots are append-only; ids hash the content.
6. Snapshots are built only for D1 views in M3 (D12).

## Acceptance tests
- The default start gives equity 100,000.00 with no positions; a declared position is valued at the right raw close for several `as_of` times, including the equal-time and delivery cutoffs.
- A missing bar, a not-yet-delivered bar, a split after the start and missing coverage each give `SnapshotUnavailable` with the reason.
- Peak equity across a rising-then-falling price series; hand-calculated drawdown.
- Same inputs give the same id; any field change gives another id; the store is append-only.
- A second starting-state declaration is refused; a non-Admin declaration is refused and writes nothing.

## Out of scope
Ledger-derived positions and P&L (M5), fees, multi-currency, fractional shares.
