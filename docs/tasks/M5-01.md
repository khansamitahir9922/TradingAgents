## Contracts

The [M5 shared contracts](M5-README.md#shared-contracts) and accepted ADR-010 govern this task. Proposed rules for this task:

1. Implement LedgerStore append/history in C2; immutable tables for batches, transactions, entries, source receipts, activation and lot-match evidence. Foreign keys prevent orphan entries and cross-account parents.
2. Deferred constraint triggers check every touched header at commit: nonempty, declared entry count/content hash, same account, nonzero one-sided entries and exact debit/credit balance for each unit. A header-only insert cannot commit. Inserting into an old transaction cannot preserve its immutable count/hash.
3. Refuse UPDATE/DELETE/TRUNCATE and conflict-update replacement; no privileged trigger disabling. Reversals must negate the full selected transaction in the original units, exactly once per correction edge.
4. Use account-control then ledger locking consistently; compare-and-set book parent/version. Entry/source/audit/outbox failure rolls back the complete batch. Emit one numbered book event per batch. No explicit commit inside a caller transaction.
5. Migration 0016 is additive. Upgrade a populated schema-0015 test database without altering existing content. The package-data wildcard already includes new SQL; do not change pyproject.toml.

## Acceptance tests

- SQL probes: balanced USD but unbalanced shares; two different instruments cancelling; empty transaction; orphan/cross-account entry; adding a balanced pair later to a sealed transaction.
- UPDATE, DELETE, TRUNCATE, ON CONFLICT DO UPDATE, altered hash, partial reversal and duplicate reversal all fail.
- Two connections append from the same parent: one succeeds or retries from the new parent; no lost update or duplicate event.
- Injected failure after each table write leaves no partial batch/source receipt/audit/event. Idempotent retry returns original saved records.
- Upgrade preserves all 0015 rows/IDs; fresh installed wheel discovers and applies 0016.
