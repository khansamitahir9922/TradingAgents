## Goal
Create the Execution Worker and the Core Engine as separate processes, each with its own entry point. Define every cross-task port the later tasks need. Make it impossible, by layering and by configuration loading, for any other path to reach the broker or the worker's secrets (Laws 1, 2; Part E; ADR-002; D32; Part J).

## Allowed files
- `investment_engine/execution/__init__.py`, `__main__.py`, `worker.py`, `broker_port.py`, `secrets.py`, `factory.py` (new)
- `investment_engine/core/__init__.py`, `__main__.py`, `engine.py` (new): the Core Engine loop (convert, publish, consume)
- `investment_engine/config.py`: the secrets-file and control-directory paths
- `tests/engine/test_layering.py`: the import rules; `tests/engine/test_execution_process.py` (new); `tests/engine/broker_doubles.py` (new, test-only): a scriptable `BrokerPort` double used by M4-03 – M4-08 and M4-11
- `docs/tasks/M4-03.md`, `PROGRESS.md`

## Contracts (the cross-task ports, all defined here)
```python
class BrokerPort(Protocol):  # the only way to a broker
    def submit(self, order: Order, *, at: datetime) -> SubmitResult            # may raise BrokerTimeout
    def cancel(self, client_order_id: str, *, at: datetime) -> CancelResult    # may raise BrokerTimeout
    def lookup(self, client_order_id: str, *, at: datetime) -> BrokerOrderReport | None   # None: no record (D20)
    def messages(self, *, after: str | None, at: datetime) -> list[BrokerMessage]       # delivered at or before `at`
@dataclass(frozen=True)
class SubmitResult: accepted: bool; broker_order_id: str | None; reason: str
@dataclass(frozen=True)
class CancelResult: outcome: str; received_at: datetime | None; reason: str
    # CANCELLED (conclusive now) | PENDING (received; the outcome is delivered later as messages) | TOO_LATE | UNKNOWN_ORDER
@dataclass(frozen=True)
class BrokerOrderReport:
    client_order_id: str; broker_order_id: str; status: str; filled_qty: Decimal; message_ids: tuple[str, ...]
@dataclass(frozen=True)
class BrokerFill:
    broker_fill_id: str; quantity: Decimal; price: Decimal; fee: Decimal; currency: str
    executed_at: datetime; provenance: str          # canonical JSON (M4-06 rule 4)
@dataclass(frozen=True)
class BrokerMessage:
    message_id: str; client_order_id: str; kind: str  # ACK | FILL | EXPIRED | CANCELLED | REJECTED
    delivered_at: datetime; fill: BrokerFill | None; reason: str
class BrokerTimeout(Exception): ...

def build_broker(kind: str, *, account_kind: AccountKind, **deps) -> BrokerPort   # factory.py: the allowlist
def load_worker_secrets(path: Path) -> Mapping[str, str]                          # called only from __main__.py
class ExecutionWorker:
    def __init__(self, db, *, clock: Clock, broker: BrokerPort, kill_switch, reads, ...): ...
    def step(self) -> StepReport
    def run(self, *, poll_seconds: Decimal, stop: Callable[[], bool]) -> None
class CoreEngine:
    def step(self) -> StepReport
```
`python -m investment_engine.execution run --broker KIND` and `python -m investment_engine.core run`.

## Rules
1. **The factory is an allowlist.** In this task it knows no production broker: `build_broker` raises "no broker adapter is available yet", and the entry point refuses to start without one. M4-06 adds `simulated`, for RESEARCH accounts only (D23); M7 adds the paper adapter. Tests use `broker_doubles.py` by building `ExecutionWorker` directly. No CLI pretends to have a simulator before M4-06.
2. **Layering** (Laws 1, 2), enforced by `test_layering.py`, with a failing fixture for each rule:
   - Nothing outside `investment_engine/execution/` imports `execution`, **except** `investment_engine/simulation/` (M4-13). That is the offline research composition harness (D24), and it may import only `execution.worker`, `execution.factory`, `execution.broker_port` and `execution.simulated_broker`.
   - Nothing at all, the harness included, imports `execution.secrets` except `execution/__main__.py`.
   - `execution` imports no `quant`, `decision`, `evaluation`, `reporting`, research or `simulation` module.
   - Nothing imports `simulation` except `intents_cli.py`.
   - Strategy, decision, portfolio, policy and risk modules never import the broker port.
3. **Secrets** (D32; ADR-002 §5). Only the worker's entry point reads `<data dir>/secrets/execution_worker.env`, which may be empty or absent for the simulator. A test starts each other entry point (`core`, `admin_cli`, `intents_cli`) with a canary secrets file present, and checks the canary never appears in its output or in its loaded configuration. Secrets are never logged. This is a development convention until M7.
4. **Processes talk only through the database** (ADR-005). They share no memory, each opens its own connection with its process role (M4-00 rule 2), and neither calls the other.
5. **Time.** `step()` reads only the injected clock: a LiveClock in the deployed processes, a ReplayClock in the harness and tests.
6. **Shutdown and crashes** (clarification). `run` exits cleanly when `stop()` is true; the entry point sets that from a signal on POSIX, and from CTRL_BREAK on Windows for a process started in its own process group. A **crash** in tests is `Popen.kill()` (TerminateProcess on Windows), never a graceful stop. Recovery never depends on graceful shutdown.

## Acceptance tests
- Each layering rule catches its fixture; the harness exception admits only the four named modules.
- The canary secrets check for `core`, `admin_cli` and `intents_cli`.
- `execution run` with no adapter refuses to start with the stated reason. A worker built with the test double runs `step()` on an empty store.
- Graceful stop on Windows and POSIX in their own way; `Popen.kill()` leaves no partial write (all writes are transactions).
- `core run` publishes pending outbox rows on start and stops cleanly.

## Out of scope
The gate (M4-05), the simulator (M4-06), OS-user isolation (M7, ADR-012).
