## Goal
Compute `DataHealth` **per provider and timeframe** (Part H; Law 9), using **only the four frozen statuses**: `OK`, `STALE`, `MISSING` and `DEGRADED`. Each source reports its age and detail, and the result includes `required_sources_ok`. Data is read as **visible at time T**, with the injected Clock, never the system clock.

**Whether a check applies at all** (e.g. the instrument isn't active at T) is reported **separately from the status**, not as a fifth status.

## How DataHealth uses SQLite
DataHealth **reads** the Operational Database (M1-05) and doesn't write to it:
- the **instrument master**, to decide applicability. Before `active_from`, or at or after `active_to`, the instrument isn't applicable at T;
- the **symbol mappings**, to know whether each provider has a mapping at T. A source with no mapping is `MISSING`, with detail "no symbol mapping for provider on date".

Bars come from the Market-Data Store via `candles_visible_at(source, …)` (M1-11), **always for one provider at a time**. Expected sessions and hours come from the calendar (M1-07).

**DataHealth results aren't persisted in M1.** Part F gives Data Quality no authoritative store. Whether snapshots are recorded for lineage is decided with lineage in M2.

## Contracts
```python
class HealthStatus(StrEnum): OK, STALE, MISSING, DEGRADED     # exactly the four frozen states (Part H)

@dataclass(frozen=True)
class SourceKey:
    provider: str; timeframe: Timeframe

@dataclass(frozen=True)
class SourceHealth:
    source: SourceKey
    status: HealthStatus
    as_of: datetime                   # the evaluation time T (UTC)
    latest_bar_end: datetime | None
    age: timedelta | None             # as_of - latest_bar_end; None when there's no bar
    bars_behind: int | None           # expected closed bars after latest_bar_end, up to as_of
    missing_in_window: tuple[datetime, ...]
    detail: str                       # the reason; never empty unless OK

@dataclass(frozen=True)
class Applicability:                  # separate from the four statuses
    applicable: bool
    reason: str                       # e.g. "EQ_US_NVDA not active before 2019-01-01"; "" when applicable

@dataclass(frozen=True)
class DataHealth:
    instrument_id: str; as_of: datetime
    applicability: Applicability
    sources: tuple[SourceHealth, ...]   # empty when not applicable: no status is invented
    required_sources_ok: bool           # False when not applicable

@dataclass(frozen=True)
class HealthThresholds:                 # configuration object; overridable by callers and the CLI
    stale_after_bars: Mapping[Timeframe, int]   # default {D1: 1, H1: 1}
    lookback_sessions: int                      # default 20

def evaluate_health(instrument_id: str, required: Sequence[SourceKey], *, clock: Clock,
                    reader: MarketDataReader, instruments: SqliteInstrumentRepository,
                    resolver: SqliteSymbolResolver, calendar: TradingCalendar,
                    thresholds: HealthThresholds = HealthThresholds()) -> DataHealth
```

## Status rules (for an applicable instrument, at `T = clock.now()`, per source)
| Status | When |
|---|---|
| `MISSING` | The provider has no mapping at T, **or** no bar of that provider and timeframe is visible in the lookback window |
| `STALE` | `bars_behind` > the threshold for the timeframe |
| `DEGRADED` | Not stale, but one or more expected bars in the lookback window are missing |
| `OK` | None of the above |

- `required_sources_ok` is true only if the instrument is applicable **and** every required source is `OK`.
- **Not applicable** ⇒ `applicability.applicable = False` with its reason, `sources = ()` and `required_sources_ok = False`. No status is fabricated.

## Implementation choices
**Resolved**
- **The four statuses stay as frozen.** Applicability is a separate field, so no contract change or ADR is needed.
- **Staleness is measured in expected bars behind**, using the calendar, so nights, weekends and holidays are never "stale". `age` is still reported.
- **Providers are evaluated independently.** One provider's bars never satisfy another provider's source.
- **Thresholds are a configuration object** with documented defaults. Final values relate to OPEN-06 and OPEN-08.
- **The required set is passed in.** In M1, the CLI passes the chosen provider's `D1` and `H1`. Strategies declare their own from M2 (Law 9).
- **`BACKFILL_ASSUMED` data doesn't affect status.** The report (M1-17) labels backfill separately.
- *Batch 4, behind against missing.* Expected bars **after** the latest visible bar count as `bars_behind` (STALE beyond the threshold). Expected bars **up to** it that are absent are holes, which make the source DEGRADED and are listed in `missing_in_window`. This is what makes "T one bar after the last expected close → still OK" hold. STALE takes precedence over DEGRADED, and `missing_in_window` is reported either way.
- *Batch 4, the lookback window.* It holds the last `lookback_sessions` sessions that **opened before T**, bounded by the calendar's coverage (never guessed past it). Hourly bars are expected on the session grid from 09:30, with the last bar ending at the close; a bar is expected once its end is at or before T.
- *Batch 4, input checks.* The required set must be non-empty and distinct. Thresholds need a non-negative integer for **every** timeframe, and a positive lookback. The defaults are immutable. An unknown instrument raises, rather than being reported as not applicable.

**Unresolved**
- **Persistence of DataHealth snapshots:** deferred to M2 (lineage).

## Acceptance tests
**Statuses:**
- a complete recent series → `OK`; with T one bar after the last expected close → still `OK`; beyond the threshold → `STALE`, with `bars_behind`;
- a weekend or holiday between the last bar and T doesn't count as behind;
- a removed session inside the lookback → `DEGRADED`, listing it;
- no bars → `MISSING`;
- no mapping for the provider → `MISSING`, with that detail.

**Applicability:**
- an instrument not active at T → `applicable = False` with the reason, no source statuses and `required_sources_ok = False`;
- the result never contains a status outside the four frozen ones (an exhaustiveness test over every code path).

**Two providers (Codex finding 4):**
- with complete `yfinance` data and no `testvendor` data, `yfinance D1` is `OK` and `testvendor D1` is `MISSING`;
- `required_sources_ok` is true if only `yfinance D1` is required, and false if `testvendor D1` is required too;
- a `testvendor` bar never fills a gap in `yfinance`.

**Other cases:**
- a correction available after T isn't used;
- a `ReplayClock` is used throughout, and the system-clock scan (M1-01) still passes.
