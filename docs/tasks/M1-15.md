## Goal
Build daily bars from one provider's hourly bars **within calendar sessions**, including half-days, using **only what was available at a stated time `at`**. Never invent data, and keep complete references to the inputs. Compare the result with the same provider's daily bars, and **report** the differences rather than resolving them.

## Rules
1. **Time cutoff.** Every input must have `available_from <= at` and `end_time <= at`. `aggregate_session` **raises** on any input that breaks this, and `resample_daily` reads only `candles_visible_at(at)`. Future bars, and corrections not available at `at`, can never enter.
2. **One provider.** Every input must have the same `source` (and the same instrument, currency, both bases, and timeframe `H1`). **Mixed providers raise**, as do mixed currencies and mixed bases.
3. **No duplicates.** More than one input for the same `start_time` raises (the reader returns one revision per identity, so this signals a caller error).
4. **Expected hourly starts** come from the calendar plus M1-13's alignment: from 09:30 in one-hour steps; the last bar is shorter, ending at the regular or half-day close.
5. **Aggregation** in Decimal:
   - open is the first input's open;
   - high is the maximum, low the minimum;
   - close is the last input's close;
   - volume is the sum.
6. **Session closed by `at` and all expected inputs present** ⇒ a `CLOSED` bar.
7. **Session still open at `at`** ⇒ a `FORMING` bar from the inputs up to `at`.
8. **Session closed but an expected input missing** ⇒ a `SessionGap`, **not** a bar. A partial day is never presented as complete.
9. **Lineage.** `inputs` lists **every** input revision as a complete `InputRef`. `available_from` is the latest input's, and `availability_basis` is `BACKFILL_ASSUMED` if any input is.

## Implementation choices
**Resolved**
- **Hourly → daily only** in M1.
- **`ResampledBar` isn't a `Candle`, and isn't stored.** It can't be confused with vendor data or written by the store (M1-08 rule 9).
- **The vendor daily series is the series of record** (M1-13). Differences are expected (e.g. the official closing auction versus the last hourly print, or venue coverage in volume) and are **reported, never silently reconciled**.
- *Batch 4, edge cases the rules left implicit, all resolved conservatively:*
  - **A session still open at `at`** gives a FORMING bar only if **every expected hour that has already ended** is present; otherwise a `SessionGap` lists the missing ones. A hole is never hidden inside a forming day.
  - **A session not yet open at `at`** gives no output.
  - **A session with no inputs** is a `SessionGap`. `aggregate_session` takes an optional `source` so that a gap with no inputs can still name its provider; with inputs, it must match theirs.
  - Inputs must sit **on the session's hourly grid** (start and end); otherwise the function raises.
  - Inputs are checked for the cutoff by **end time first, then availability**; both raise.
- *Batch 4, `compare_daily`:*
  - It compares only **CLOSED** resampled bars.
  - It requires each bar's `as_of` to equal `at` (the same cutoff) and its `source` to be the requested provider.
  - It has an optional, keyword-only session range (`first_session`, `last_session`, `calendar`). With it, a vendor day whose resampled side is a gap is reported as `missing_resampled`; without it, the range is the resampled bars' own sessions. This adds to the spec's signature without changing it.

**Unresolved:** none.

## Acceptance tests

**Review follow-up:** reader rows must match the requested provider, instrument and timeframe. A comparison also validates the resampled input references, rejects duplicate sessions, and requires matching currency, field bases and session boundaries. Incompatible inputs raise; they cannot be reported as numeric differences.
**Basic sessions:**
- a regular session with all inputs gives a CLOSED bar, with aggregation checked field by field;
- a half-day expects inputs only until 13:00.

**Gaps and forming bars:**
- a missing middle hour in a closed session gives a `SessionGap`, and no bar;
- `at` during the session gives a FORMING bar built only from bars that ended by `at`.

**Cutoff (Codex finding 5):**
- a bar ending after `at`, passed directly to `aggregate_session`, raises;
- a correction with `available_from > at` isn't used by `resample_daily`: the output uses revision 1, and `inputs` shows revision 1;
- when `at` is after the correction, the output uses revision 2.

**Providers and consistency:**
- inputs from `yfinance` and `testvendor` together raise;
- `compare_daily` with a `testvendor` daily series reads only `testvendor` vendor bars;
- mixed currency or basis raises, and a duplicate `start_time` raises.

**Lineage.** `inputs` holds every input with source, instrument, timeframe, start time, revision, import ID and availability.

**`compare_daily`:**
- identical bars → no differences;
- a different close → one difference;
- a missing vendor day → `missing_vendor`;
- vendor bars not yet available at `at` are treated as missing.
