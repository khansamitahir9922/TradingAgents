## Goal
Deliver M1's visible result (Part K): a command-line tool that replays **NVDA** from stored data and prints clean daily and hourly candles plus a DataHealth report, **for one named provider**. Every value carries its source, basis and time, and nothing is invented (design principles, Sections 2–5).

## Contracts

### Commands (`python -m investment_engine …`)
| Command | Network | Does |
|---|---|---|
| `init` | No | Creates or updates the SQLite schema (M1-05) and loads the seed: instrument `EQ_US_NVDA` and its `yfinance` mapping. Idempotent. |
| `import-yfinance --instrument EQ_US_NVDA [--daily-from 2019-01-01]` | **Yes** | Runs M1-12's action import, then M1-13's daily and hourly bar imports. Prints each report. A **blocked field stops the affected import** and is reported (M1-12, "If verification blocks"). |
| `report --instrument EQ_US_NVDA [--provider yfinance] --timeframe D1\|H1 --from DATETIME --to DATETIME [--as-of DATETIME] [--latency SECONDS]` | **No** | Replays `[from, to)` with `ReplayFeed` (M1-14) for the one provider, and prints what replay delivered. Also prints corporate actions, the vendor-vs-resampled daily comparison at the cutoff (M1-15, for D1) and DataHealth at `--as-of` (M1-16). |

### Report content
**Header:**
- instrument, exchange and **provider**;
- the replay window (half-open, by delivery time);
- `as-of` in ET and UTC;
- a labels line: `PAPER-ONLY PLATFORM · RESEARCH DATA (<provider>) · REPLAY`.

**Candles** (one row per delivered `BAR_CLOSED`):
- start and end in ET, with UTC available;
- O, H, L, C in USD, and volume in shares;
- state and revision;
- **price basis and volume basis**;
- availability basis;
- the stored observation time;
- the replay `received_at`.

**Labels:**
- `BACKFILL_ASSUMED` rows: "BACKFILL · availability assumed at bar close; original publication time unknown".
- Each basis is explained once, e.g. "RAW, reconstructed from Yahoo's split-adjusted data". The explanation includes the **precision note** from `docs/data-provenance/yfinance.md`.

**Corrections and corporate actions.** Delivered `CANDLE_REVISED` events are listed with their arrival time and the before and after values. Corporate actions are listed with their basis and availability.

**Health.** One line per source: status (one of the four), `latest_bar_end`, `age`, `bars_behind`, missing bars and detail, plus `required_sources_ok`. **Applicability is printed on its own line** (e.g. "Health checks not applicable: EQ_US_NVDA not active before …"), never as a status.

**Honesty rules** (design principles H-01, H-02):
- A missing value prints `UNAVAILABLE` or `— NOT YET` with a reason, never `0`.
- An empty window says "no bars delivered in this window".
- Nothing is printed that isn't in the store or derived by a named function.

## Implementation choices
**Resolved**
- **Typer and Rich**, already project dependencies. There's **no new console script**: `python -m investment_engine` avoids touching `[project.scripts]`.
- **`report` is fully offline.** It uses stored data and SQLite only. `--provider` defaults to `yfinance`, and the report never mixes providers.
- **`--as-of` defaults to `LiveClock().now()`.** The CLI is the entry point that may construct a `LiveClock`, and replay uses a `ReplayClock`. `--to` must be at or before `--as-of`.
- **If the optional `engine` dependencies are missing**, the store commands print how to install them (`pip install -e ".[engine]"`) and exit with a non-zero code.
- **Seed data:** `EQ_US_NVDA`, `EQUITY`, `USD`, `XNAS`, `America/New_York`, `ACTIVE`, with mapping `yfinance:NVDA`. `active_from` and the mapping's `valid_from` are NVDA's listing date **if confirmed from a cited source while writing the seed**. Otherwise they're `2019-01-01`, marked in the file as a lower bound of verified coverage, not the listing date.

- **Listing date confirmed:** NVIDIA's investor FAQ gives January 22, 1999 and the Nasdaq symbol NVDA. The packaged seed cites that primary source and records the retrieval date. The separately verified Yahoo import boundary remains 2019-01-01.

**Unresolved**
- Hourly fields and full vendor-vs-hourly comparison remain blocked. The daily-only CLI does not resolve their evidence/permission gates.

## Acceptance tests (Typer `CliRunner`, `tmp_path` data directory, fixture data written through the real writer)
- `init` twice → one instrument and one mapping.
- `report --timeframe D1` on fixture data prints the expected bars, with revision, both bases and the BACKFILL label.
- **Friday correction** (fixture):
  - a window ending Thursday shows revision 1 and no correction;
  - a window ending Saturday also lists the correction, arriving Friday 21:00 UTC.
- **Health:**
  - a removed session gives `DEGRADED` with that date;
  - an empty store gives `MISSING` and "no bars delivered", never zeros;
  - an `--as-of` before `active_from` prints the "not applicable" line and no statuses.
- **Two providers:** with both `yfinance` and `testvendor` fixtures stored, `--provider testvendor` shows only `testvendor` bars, health and corrections.
- **Blocked import:** with a synthetic `YAHOO_VERIFICATION` that blocks `H1_PRICE`, `import-yfinance` imports actions and daily bars, refuses hourly with the reason, and exits non-zero.
- Missing `engine` dependencies (simulated) give the install message and a non-zero exit.
- `report` runs with the network guard on, which proves it's offline.
- **End to end:** `init`, a fixture import, `report D1`, `report H1`, and the health output.
