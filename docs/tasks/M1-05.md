## Goal
Persist the instrument master and symbol mappings in the Operational Database: SQLite in M1–M2 (ADR-008), written so the M3 move to PostgreSQL is mechanical. Define where the platform keeps its data on disk.

## Allowed files
- `investment_engine/config.py` (new)

- `pyproject.toml`: **only** `[tool.setuptools.package-data]`, adding `investment_engine = ["storage/schema/*.sql"]`

## Contracts
```python
# config.py
ENV_DATA_DIR = "INVESTMENT_ENGINE_DATA_DIR"
def data_dir() -> Path             # $INVESTMENT_ENGINE_DATA_DIR, else Path.home() / ".investment_engine"
def operational_db_path() -> Path  # data_dir() / "operational.sqlite3"
def market_store_dir() -> Path     # data_dir() / "market"

# storage/sqlite.py
def open_operational_db(path: Path) -> sqlite3.Connection   # foreign_keys=ON; creates parent directory
def apply_schema(conn) -> int      # applies pending numbered scripts in order; returns the schema version;
                                   # a database newer than the code raises
class SqliteInstrumentRepository:
    add(instrument), get(instrument_id), list(), update_lifecycle(instrument_id, status, active_to)
class SqliteSymbolResolver:        # same interface as M1-04's SymbolResolver
    add(mapping), resolve(provider, symbol, on), symbol_for(instrument_id, provider, on)
```
**Tables** (`0001_reference_data.sql`): `schema_version(version)`, `instruments(...)` (primary key `instrument_id`), `symbol_mappings(...)`. Dates are stored as ISO-8601 `TEXT`. Check constraints mirror M1-03 and M1-04 where SQL can express them.

## Implementation choices
**Resolved**
- **Stdlib `sqlite3`, no ORM.** There's no new dependency.
- **Forward-only numbered SQL scripts** plus a `schema_version` table. That's simple, reviewable and portable.
- **Portable SQL only:**
  - no `INSERT OR REPLACE`, `AUTOINCREMENT` or SQLite-only functions;
  - standard `CHECK`, `PRIMARY KEY` and `FOREIGN KEY`.

  Overlap checks run in application code inside one transaction, reusing M1-04's rules.
- **No `DELETE` path.** Instruments change only through `update_lifecycle` (status and `active_to`), which keeps IDs from ever being reused.
- **Default data location is outside the repository** (`~/.investment_engine/`), overridable by environment variable. `tests/engine/conftest.py` sets `INVESTMENT_ENGINE_DATA_DIR` to a temporary folder (autouse), so no test touches the home folder. That follows the existing `tests/conftest.py` pattern.

**Unresolved:** none.

## Acceptance tests
- A schema applied twice is idempotent, and the version is recorded. A database with a higher version than the code raises.
- An instrument and mappings round-trip through SQLite. `SqliteSymbolResolver` passes the **same test cases as M1-04**, through a shared parametrised test.
- Overlapping mappings are rejected, and the failed transaction leaves no partial rows.
- A duplicate `instrument_id` is rejected. There's no delete method.
- `data_dir()` honours the environment variable, and `tests/engine/conftest.py` keeps tests out of the home folder.
- A test greps the schema script for the non-portable constructs listed above.

## Out of scope
- Market data, which lives in the Parquet store (M1-10).
- DataHealth persistence, which isn't stored in M1 (see M1-16).
- PostgreSQL (M3).
- Concurrent writers: M1 assumes one writing process.
