## Goal
Copy an existing M1–M2 SQLite Operational Database into PostgreSQL without changing any record or id, and make the CLI use PostgreSQL.

## Allowed files
- `investment_engine/storage/copy_sqlite.py` (new)
- `investment_engine/config.py`: `operational_db_dsn()` and its variable
- `investment_engine/cli.py`: the database opening in existing commands, and a new `db` command group (`db status`, `db copy-from-sqlite`)
- `tests/engine/test_copy_sqlite.py` (new)
- `tests/engine/test_cli.py`, `tests/test_cli_commands.py`: backend set-up only; no assertion weakened
- `docs/dev/postgresql.md`, `docs/tasks/M3-03.md`, `PROGRESS.md`

## Contracts
```python
ENV_PG_DSN = "INVESTMENT_ENGINE_PG_DSN"
def operational_db_dsn() -> str        # raises with a pointer to docs/dev/postgresql.md if unset; never echoes the value

@dataclass(frozen=True)
class CopyReport:
    source_path: Path; source_schema: int; target_schema: int
    copied: Mapping[str, int]; already_present: Mapping[str, int]; verified_ids: int

def copy_sqlite_to_postgres(sqlite_path: Path, target: Database) -> CopyReport
```

## Rules
1. **The source is never changed.** SQLite is opened read-only (`mode=ro`). Nothing is deleted or rewritten there.
2. **Exact copy.** Instruments, symbol mappings, lineage records and evaluation records are copied with identical ids and content bytes. Each copied lineage and evaluation record is then read back through its store on PostgreSQL and must hash to its id (both evaluation formats; R1). One failure rolls the whole copy back.
3. **Re-runnable and safe.** A row already present with identical content is counted as present; a different row under the same id stops the copy with a conflict and changes nothing. The copy runs in one transaction.
4. **Schema gate.** The source must be at SQLite schema 1–4; a newer schema raises. The target is migrated to the current PostgreSQL version first.
5. **The CLI uses PostgreSQL.** `init` and the replay and report commands open `PostgresDatabase(operational_db_dsn())`. The market-data store (Parquet) is unchanged. `db status` prints the schema version and row counts, never the DSN. `db copy-from-sqlite PATH` prints the CopyReport.
6. SQLite stays only for reading old files and for the dual-backend store tests (M3 README, "For review" item 2).

## Acceptance tests
- A SQLite database built with M2's code (lineage records, both evaluation formats, reference data) copies exactly; a second run reports everything already present; the source file's bytes are unchanged.
- A conflicting target row aborts with nothing copied; a corrupted source record (hash mismatch) aborts with nothing copied.
- A source at schema 5 is refused.
- `init` and the daily report work against PostgreSQL; an unset DSN gives the documented message without any DSN text; output never contains the test DSN's password.

## Out of scope
Copying the market-data store (unchanged), production migration runbooks (M7).
