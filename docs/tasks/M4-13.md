## Goal
M4's visible result: a replay of NVDA's daily history through the full order path to the simulated broker, on a RESEARCH account at Level 2, with an order log that explains every order (Part K M4; D23, D24; PRD UC-11, at M4; Law 20; design principles T-01 – T-04).

## Rules
1. **The harness's narrow scope** (D24; Codex answer 2). It is an offline research and test orchestration, not a deployment topology.
   - It builds the unchanged Core Engine and Execution Worker role objects, each with its own connection, process role and stores. They exchange work only through database rows, and only worker code calls the broker port.
   - It builds the broker only through `execution.factory.build_broker("simulated", account_kind=RESEARCH)`, never a PAPER or live adapter, and never loads secrets.
   - The deployed processes stay separate (M4-03), and the real two-process path is proved in M4-08 and M4-12.
2. **The phases of each session `d`**, on one ReplayClock (B5):
   1. **Before `d`'s open:** worker step, which gates and submits the orders targeting `d`. The gate requires pre-open submission (M4-05 rule 1.7).
   2. **At `d`'s decision moment** (M4-06 rule 6: the first time its CLOSED bar is actually known, delivery latency included), or at the cutoff: worker step, which ingests fills and expiries.
   3. **Then the Core role:** knowledge through that time, a provisional snapshot that **includes the fills just ingested** (M4-09), proposals for the views generated from `d`'s bar, Level 2 approval, conversion and publishing.
   4. Then on to the next session's phase 1.

   Fills are always ingested before the next proposal is sized.
3. **RESEARCH only** (D23). PAPER is refused. The kill switch is read from the real flag (ADR-006), so a disabled flag gate-rejects every order, and the run says so.
4. **Corporate actions** (D34). A range in which the projection becomes Unavailable stops proposing for the affected account from that date. The causes are: missing coverage, a fractional split, an unsupported action, or an unresolved order crossing an action (M4-09 rule 3). The log says so, with the reason, and the run doesn't silently continue.
5. **The order log** (T-01 – T-04). It reads only the order store, intents, lineage and audit: never the simulator's private tables.
   - **Header:** the provider and source; instrument; range; run cutoff and timezone (UTC, with exchange time beside it); code, calendar, strategy, decision-policy, limits, fee-schedule and fill-model versions; the kill-switch reading; and the promotion status (M4-10).
   - **For each order:**
     - the intent version and lineage id;
     - the gate decision with every check;
     - each transition, with its time and owner;
     - each fill, with quantity (shares), price and fee (USD), executed, delivered and recorded times, the timing basis, slippage and the bar reference from its provenance;
     - anomalies;
     - the final state.
   - **Summary:** counts by final state; filled notional (USD); fees (USD); UNKNOWN orders ("UNRESOLVED: broker has no record", D20); corporate-action adjustments and any stop (rule 4).
   - **Label, ASCII only:** `SIMULATED | RESEARCH | NOT PROMOTED | PROVISIONAL POSITIONS`. `--json` writes the same content.
6. **Reproducible.** The same database state and inputs give the same orders, ids and log, byte for byte. Re-running a range on an account that already has a run is refused.
7. **Honest about scope.** The provisional P&L comes from fills (D29). The ledger and reconciliation are M5's.

## Acceptance tests
- **A short fixture range,** hand-checked: one open fill, one intraday-touch fill (stamped at the close), one gate rejection and one expiry. The next proposal after a fill is sized on the post-fill portfolio.
- A missing bar gives an expiry at the cutoff; a range crossing a covered dividend gives a receivable; a fractional split stops proposals, with the reason in the log.
- With the flag disabled: every order is GATE_REJECTED, and cancels aren't blocked.
- Determinism: two fresh runs give identical logs.
- The CLI: PAPER is refused; the header, labels and units are present; the output is ASCII-only; the JSON round-trips.
- The reporter never reads schema `sim_broker` (grep test).
- Optional, run once and recorded, not asserted: the full 2019–2026 NVDA range, with its summary in PROGRESS.

## Out of scope
HTML charts, ledger P&L (M5), live-clock simulated paper trading (no live data before M7).
