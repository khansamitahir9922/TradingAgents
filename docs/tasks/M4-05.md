## Goal
A deterministic, cheap check inside the Execution Worker before every submission. It covers every condition in Law 13, with typed inputs that keep "unavailable" apart from "false". A locking protocol makes sure that no control change, fill or new reservation can commit between the gate's reads and its decision. Each check that ran is recorded with its inputs (Law 13; ADR-004 §4; G1 step 11).

## Contracts
```python
@dataclass(frozen=True)
class Missing: reason: str                       # an unavailable read; never confused with False
Observed = T | Missing

@dataclass(frozen=True)
class GateInputs:  # every field read fresh, under the rule 4 locks
    account_kind: AccountKind                    # from the order (immutable)
    latest_version: Observed[int]; intent_state: Observed[IntentState]; intent_content_id: Observed[str]
    approval_expires_at: Observed[datetime]; view_valid_until: Observed[datetime]
    reference_current: Observed[bool]            # the decision bar is still its latest known revision
    action_since_reference: Observed[bool]       # a split or dividend ex-date in (decision session, target session]
    risk_version: Observed[str]; policy_version: Observed[str]; autonomy_setting: Observed[str]
    halted: Observed[bool]; restricted: Observed[bool]
    promotion: Observed[str] | None              # PAPER only; None for RESEARCH (D23)
    fingerprint_now: Observed[str]               # FingerprintProvider.at(account, at, excluding_order=this order)
    pending_cancel: Observed[bool]; session: Observed[SessionWindow]

def check_gate(order: Order, status: OrderStatus, *, at: datetime, inputs: GateInputs,
               intent: StoredIntent, kill_switch: FlagReading) -> GateDecision     # pure
class GateReadProvider(Protocol):
    def read(self, order: Order, *, at: datetime) -> GateInputs                    # inside the caller's transaction
```

## Rules
1. **The checks, in this order; all of them run and are recorded:**
   1. `kill_switch`: the reading is enabled.
   2. `intent_version`: the latest version equals the order's, the state is CONVERTED, and the content id equals the order's pinned `intent_content_id` (Law 12).
   3. `approval`: `at < approval_expires_at`.
   4. `view`: `at < view_valid_until`, `reference_current` is True, and `action_since_reference` is False. A corporate action between the decision bar and the target session makes the raw reference price stale (B6).
   5. `controls`: the risk, policy and autonomy identities effective at `at` equal the intent's. `halted` is False for a BUY, `restricted` is False, and, for PAPER, `promotion` is accepted.
   6. `positions`: `fingerprint_now` equals the order's pinned `position_fingerprint` (Law 13: "no position change since").
   7. `session`: DAY only. The target session is a regular session, and `at` is after the decision bar's close and **strictly before the target session's open** (D25: the daily fill model only models orders resting from the open; B5).
   8. `cancel`: `pending_cancel` is False. A cancel before submission fails the gate, and nothing is sent.
2. **Missing is not False** (Law 9). A `Missing` input fails its check with "unavailable: <reason>". A boolean check passes only on an observed value.
3. **The fingerprint** (B4) is `economic_fingerprint` (M4-02): cash, whole-share positions and open-order reservations, with no valuation, time or provenance. At the proposal, this order didn't exist. At the gate, the provider excludes this order. Both sides therefore exclude it, and an unchanged portfolio gives an equal fingerprint whatever the time or prices.
4. **The lock and read protocol** (B4). The worker's gate transaction runs at READ COMMITTED:
   1. take the account-control advisory lock (M3-05 rule 6);
   2. lock the order row `FOR UPDATE`;
   3. **only then** read every input fresh with `GateReadProvider.read`;
   4. decide;
   5. write the decision row and its edge (NEW → SUBMITTING or GATE_REJECTED) by compare-and-set;
   6. commit.

   Every writer that can change a gate input already takes, or now takes, the same account-control lock first: M3's limit, rule, autonomy, halt and restriction changes; conversion (M4-02, which creates reservations); and the worker's fill and terminal-state writes (M4-07, which change positions or reservations). A change therefore commits entirely before the gate's reads, which then see it, or entirely after the decision. A snapshot taken before waiting for a lock is never used. The kill-switch file is read after the locks, inside step 3.
5. **Pure and deterministic.** `check_gate` does no I/O and reads no clock. The same inputs give the same decision and the same canonical `inputs` text.
6. **The gate never reruns the strategy**, and never resizes or reprices (ADR-004 §4). **Cancels bypass the gate** (Law 15).

## Acceptance tests
- Each check fails alone in a minimal case, with its reason, and all eight are recorded every time.
- **Expected values, per input:** `reference_current` must be True; `action_since_reference`, `halted` (for a BUY), `restricted` and `pending_cancel` must be False. Each version, setting and content-id input must equal its pinned value, and each time input must lie in its window. For every input, an observed wrong value fails its check with that value, and `Missing` fails it as "unavailable", independently.
- Unchanged state: the same portfolio at a later time and other prices gives an equal fingerprint, and the gate passes.
- Boundaries: exactly at the expiry, at `view_valid_until` and at the target open, rejected; one microsecond before, passed. A corporate action ex-date in the window is rejected.
- **Two-connection interleavings on PostgreSQL, 20 repetitions each**:
  - a limits publish against the gate;
  - a fill on another order of the account against the gate;
  - a new conversion (a new reservation) against the gate.

  Either the change commits first and the gate rejects (`controls` or `positions`), or the gate decides first and the change commits after. Never a pass on a superseded read.
- Determinism: the same inputs give byte-identical decisions.
