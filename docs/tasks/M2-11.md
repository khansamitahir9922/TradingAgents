## Goal
Evaluate fixed rule strategies in chronological folds, record every assumption and prevent incomplete outcomes, later revisions or fitting from crossing a fold boundary. This supplies a future promotion prerequisite; it never performs promotion.

## Rules
1. Month boundaries are calendar months aligned to the first covered session; a fold's training cutoff is strictly before test start. Fixed rules use training data only for warm-up; they are not refitted. Build test decisions with historical PIT reads at each prediction T. Test-period realised outcomes belong to evaluation only.
2. If an experiment later introduces cleaning, imputation for optional research inputs, feature selection, tuning or calibration, fit it exclusively on eligible training data within the fold. No preprocessing fit on the whole dataset. Required sources are never imputed: Law 9 still abstains. The M2 runner rejects unsupported fit steps rather than silently accepting an unguarded transformer.
3. Purge training examples unless both outcome completion and input availability are <= training cutoff (M2-08). Five-session labels starting just before test start cannot be smuggled into training. Any overlapping-label dependence and excluded counts are reported.
4. Test observations are non-overlapping across folds. Include warm-up history without counting it as test performance. Each fold starts with declared fresh cash, not a concealed position inherited from an unevaluated train period. Report fold metrics separately; stitched normalized returns are a distinct labelled summary, not a continuous portfolio's dollar P&L. A terminal outcome missing its full horizon is unavailable, not truncated into a shorter label.
5. Store immutable run configuration, fold boundaries, raw and adjusted input references, decision lineage IDs, code/calendar/coverage versions, costs, backfill assumptions, baseline samples and metrics. IDs hash canonical content. Identical append is a no-op; conflicting ID raises; SQL triggers reject update/delete. Package migrations use the existing loader and smoke checks.
6. OPEN-09 proposals (Sharpe >=0.5, drawdown versus buy-and-hold, >=30 trades, >=60% positive test windows, three-month shadow duration) remain **UNACCEPTED** planning inputs. Display `PROMOTION NOT ASSESSED: thresholds pending approval`. Even accepted numerical tests later cannot bypass the frozen shadow/paper sequence, portfolio, policy, risk, human approvals or execution gate.

## Implementation choices
Resolved: fixed NVDA universe, fixed strategy versions, deterministic folds. Failed/warm-up/incomplete folds are reported, never dropped from the denominator without explanation. No numeric-return model or probability calibration is implemented in M2.

Unresolved: exact fold windows, aggregation conventions and promotion criteria under OPEN-09; confirmation that this work fits one task or needs a task-spec split.

## Acceptance tests
- A chronological synthetic dataset with fold edges verifies train/test separation, session alignment and no overlapping test observations.
- Labels whose horizons finish after training cutoff, or arrive later, are purged; adding future corrections doesn't alter training inputs or earlier test predictions.
- A deliberately global preprocessing fit and required-source imputation are rejected. Fit-free rule runs are deterministic.
- Missing final-horizon data, warm-up, no-trade folds and abstentions appear in counts and limitations.
- Every recorded run reconstructs its config/references; append idempotence, conflict rejection, direct-SQL immutability, existing-data migration and installed-schema smoke check.
- No output says promoted or starts paper trading when OPEN-09 is pending.

## Out of scope
ML fitting/calibration (M9), automatic promotion, broker execution and M3/M4 infrastructure.
