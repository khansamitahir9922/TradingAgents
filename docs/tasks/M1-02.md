## Goal
Implement ADR-007: money and quantities are `Decimal` with an explicit currency or unit, and conversion to and from `float64` happens only through explicit converters with a stated precision and rounding rule.

## Implementation choices
**Resolved**
- **Decimal only in constructors.** `Money(0.1, "USD")` raises, which forces every float through `from_float64`.
- **`from_float64` uses `Decimal(repr(value))`** (the shortest round-tripping representation), not `Decimal(value)`, which carries binary noise. It then quantizes **explicitly**.
- **Rounding is `ROUND_HALF_EVEN`**: unbiased over many values, and the usual financial default. It's stated once, here.
- **Price quantum `0.0001`**: US equities quote in sub-penny increments below $1, so 4 decimal places hold every as-traded US equity price exactly.
- **Share quantum `1`**: whole shares for volumes. Fractional positions belong to the ledger model (ADR-010), not M1.
- Units for ledger accounts (instrument-denominated quantities) are left to ADR-010.

**Unresolved:** none.

## Acceptance tests
- `Money(Decimal("0.1"), "USD") + Money(Decimal("0.2"), "USD") == Money(Decimal("0.3"), "USD")`.
- A float or int amount raises `TypeError`. A bad currency code raises `ValueError`.
- Mixing currencies or units in `+`, `-` or an **ordering comparison** (`<`, `<=`, `>`, `>=`) raises. **Equality** (`==`) between different currencies or units returns `False`; it doesn't raise.
- `from_float64(0.1 + 0.2, PRICE_QUANTUM) == Decimal("0.3000")`.
- Half-even cases: `quantize(Decimal("0.00005"), PRICE_QUANTUM) == Decimal("0.0000")` and `quantize(Decimal("0.00015"), PRICE_QUANTUM) == Decimal("0.0002")`.
- `from_float64(nan)` and `from_float64(inf)` raise.
- `to_float64(Decimal("123.4567")) == 123.4567`.
