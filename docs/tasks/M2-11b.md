## Goal
Store each walk-forward evaluation run immutably in the Operational Database's evaluation domain, so every reported number can be reconstructed from its recorded configuration, folds, references and versions.

## Contracts
Final interfaces (Codex accepted the whole-walk-forward record in principle):
```python
@dataclass(frozen=True)
class EvaluationRecord:
    walk_forward_config; evaluation_config; result: WalkForwardResult; source; instrument_id; as_of
    code_version; calendar_version; coverage_evidence_refs; coverage_reason; backfill_assumption
    record_id: str   # "eval-" + SHA-256 of canonical content
def check_fold_periods(record: EvaluationRecord, calendars: Mapping[str, Calendar]) -> None
class EvaluationRunStore:
    def __init__(self, conn, *, calendars: Mapping[str, Calendar])
    def append(self, record: EvaluationRecord) -> None
    def get(self, record_id: str) -> EvaluationRecord
    def ids(self, instrument_id: str) -> list[str]
```
A record must agree with every fold it holds (B5). Each fold's run must cover exactly the sessions of its half-open test window on the calendar the record declares (`calendars[record.calendar_version]`): its first session opens at `test_start` and the session after its last opens at `test_end`. Shorter, longer or shifted runs are refused on append, on read and by the report (Codex re-review R2); an unfinished fold requests its whole window and is reported incomplete (B3). Partial-window evaluations are not supported. Records of the `57d4316` format stay readable under their original ids (R1; see M2-09).

## Rules
[M2-11](M2-11.md) rule 5: IDs hash canonical content; an identical append is a no-op, a conflicting ID raises; SQL triggers reject UPDATE and DELETE; migrations use the existing numbered loader. Since B1: inserts of an existing id are refused at the schema boundary too (migration 0004), independent of the connection's recursive-trigger setting.
