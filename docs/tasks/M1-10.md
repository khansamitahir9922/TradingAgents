## Goal
Store candles and corporate actions in the Market-Data Store (Parquet; Part E) **append-only**: history is never overwritten (Law 8, ADR-009). This is the **one place** that assigns revision numbers and enforces "later revisions are never backdated". It numbers revisions **per provider**, so different providers' records never mix.

## Contracts
```python
@dataclass(frozen=True)
class CandleObservation:                 # what an importer saw; revision and availability not yet assigned
    values: <all Candle value fields, incl. source, except revision / available_from / availability_basis>
    received_at: datetime                # UTC observation time
    backfill_available_from: datetime | None   # for a first-seen historical record; None = observed live

@dataclass(frozen=True)
class ActionObservation: ...             # the same idea for CorporateAction

@dataclass(frozen=True)
class WriteResult:
    new_records: int; new_revisions: int; unchanged: int; import_id: str

class MarketDataWriter:
    def __init__(self, root: Path)
    def write_candles(self, observations: Sequence[CandleObservation], import_id: str) -> WriteResult
    def write_corporate_actions(self, observations: Sequence[ActionObservation], import_id: str) -> WriteResult
```

**Identity** (revisions are numbered per identity):
- candles: `(source, instrument_id, timeframe, start_time)` (M1-08);
- actions: `(source, instrument_id, action_type, ex_date)` (M1-09).

**Revision assignment, per identity:**

| Situation | Result |
|---|---|
| Identity not stored before | Revision 1. `BACKFILL_ASSUMED` with `available_from = backfill_available_from` when given; otherwise `OBSERVED` with `available_from = received_at` |
| Identity stored; compared values identical | Nothing written (`unchanged`) |
| Identity stored; values differ | Revision n+1, **always `OBSERVED`, `available_from = received_at`**. Any backfill time supplied is ignored, so a correction is never backdated. |

**Compared values:**
- candles: OHLC, volume, currency, price basis and volume basis;
- actions: ratio, amount, amount basis and new symbol.

Provenance fields (`import_id`, `source_version`, `received_at`, `processed_at`) are never compared. Records are only compared **within the same identity, so within one provider**.

**File layout** (the provider is the first partition):
```
<root>/candles/source=<provider>/instrument_id=<id>/timeframe=<tf>/import=<import_id>.parquet
<root>/corporate_actions/source=<provider>/instrument_id=<id>/import=<import_id>.parquet
```
Each write creates **new files only**. It writes to a temporary name and renames atomically, and **refuses if the target exists**. Existing files are never opened for writing.

## Implementation choices
**Resolved**
- **`pyarrow` and `duckdb` go in an optional extra `engine`**, also listed in `dev`, rather than in core dependencies:
  - the TradingAgents install stays as lean as upstream;
  - the CI test job (`.[dev]`) gets them;
  - the unchanged clean-install smoke job still passes, because the package import doesn't load them. `test_optional_imports.py` checks this in a subprocess.
- **Exact decimals on disk:** prices as `decimal128(18, 4)`, volume as `decimal128(20, 0)`, times as `timestamp[us, UTC]`. There are no floats in storage.
- **The writer requires values already quantized and a valid provider `source`** (M1-08 rules 3 and 9). It never rounds and never stores derived candles.
- **The latest-revision lookup inside the writer is private.** The public read API is M1-11.
- **One writer process at a time** in M1, as documented.

**Unresolved**
- **Version floors** for `pyarrow` and `duckdb`: set to versions with wheels for Python 3.11–3.14 on Windows and Linux, **checked during this task** and recorded in `PROGRESS.md`. If either lacks 3.14 wheels, the task stops and reports, because the CI matrix includes 3.14.

## Acceptance tests
- First write → revision 1 with the right basis. An identical rewrite → `unchanged`, with no new files.
- A changed close → revision 2, `OBSERVED`, `available_from == received_at`, **even when the observation carries a backfill time**. Revision 1 is still stored, unchanged.
- The same for a corporate action (a changed dividend amount).
- **Two providers:**
  - `yfinance` and `testvendor` bars for the same instrument and start time with **different** closes → **both are revision 1**, and neither is a correction of the other;
  - a later change in `testvendor`'s value → `testvendor` revision 2 only.

  The same is tested for corporate actions.
- Every existing file's bytes and modification time are unchanged after any later write (a hash check).
- A `FORMING` candle, unquantized values, or an invalid `source` are rejected.
- Decimals round-trip exactly.
- `import investment_engine` in a subprocess doesn't load `pyarrow` or `duckdb`.

## Out of scope
Public reads (M1-11), compaction, concurrent writers, cloud storage.
