## Contracts
```python
class AccountKind(StrEnum): RESEARCH = "RESEARCH"; PAPER = "PAPER"     # D15
class Role(StrEnum): ADMIN = "ADMIN"; TRADER = "TRADER"; VIEWER = "VIEWER"

@dataclass(frozen=True)
class Account:
    account_id: str; kind: AccountKind; currency: str     # "USD" in v1
    created_at: datetime

@dataclass(frozen=True)
class AutonomySetting:
    account_id: str; level: int          # 0, 1 or 2; 3 and 4 are refused in v1
    effective_at: datetime; set_by: str; reason: str

@dataclass(frozen=True)
class Operator:
    operator_id: str; role: Role; active: bool; changed_at: datetime

class AccountRegistry:
    def __init__(self, db: Database, audit: AuditStore, clock: Clock) -> None
    def create_account(self, account_id, kind, currency, *, by: Actor, reason: str) -> Account
    def set_autonomy(self, account_id, level, *, by: Actor, reason: str) -> AutonomySetting
    def autonomy_at(self, account_id, at: datetime) -> AutonomySetting        # latest effective_at <= at
    def bootstrap_admin(self, operator_id, *, os_user: str) -> Operator       # only while no operator exists
    def add_operator(self, operator_id, role, *, by: Actor, reason: str) -> Operator
    def deactivate_operator(self, operator_id, *, by: Actor, reason: str) -> Operator
    def operator(self, operator_id, at: datetime) -> Operator
```

## Rules
1. **Default Level 0.** A new account starts at Level 0 (advisory). Levels 3 and 4 always raise "disabled in v1". A RESEARCH account may use Levels 0–2 for replay demonstrations; a PAPER account's level only matters once a strategy is promoted (M3-10, D15).
2. **Admin only.** Creating accounts, setting autonomy and managing operators require an active ADMIN operator (PRD §4). Every change is a new row (autonomy history and operator history are append-only) plus an AuditEvent in the same transaction.
3. **Bootstrap.** `bootstrap_admin` works once, only while no operator exists. It's audited with actor PROCESS `admin-cli` and the OS user. Afterwards it raises.
4. **No deletes.** Accounts and operators are never deleted and ids are never reused. An operator is deactivated, and an inactive operator can't act.
5. **CLI.** `accounts create|set-autonomy|show|list` and `operators bootstrap-admin|add|deactivate|list`, each requiring `--operator ID` (except bootstrap) and `--reason` for changes. Output is plain ASCII and states "Level N (Advisory | Approved paper | Automatic paper)" and the account kind.

## Acceptance tests
- Default level 0; levels 3, 4, -1 and 5 refused; history answers "what was the level at T" across changes.
- A Trader or Viewer can't change anything; an inactive Admin can't; each refusal changes nothing and writes no event.
- Every successful change writes exactly one AuditEvent with before and after, in the same transaction (rolled back together on a forced failure).
- Bootstrap works once; ids can't be reused.
- CLI happy paths and refusals, against PostgreSQL.

## Out of scope
