## Contracts

The [M5 shared contracts](M5-README.md#shared-contracts) and accepted ADR-010 govern this task. Proposed rules for this task:

1. Store immutable comparison results, incident identities and CAS transitions with audit/outbox in one transaction, following C5 and proposed D38.
2. Creation and transitions lock account-control then incident. Admin commands then lock operator|actor_id, obtain current live command time and reauthorize stored operator state. Re-read book/snapshot evidence under lock before resolution; a newer mismatch cannot be cleared by stale evidence. Replay time cannot revive a deactivated Admin; Trader/Viewer cannot acknowledge/resolve.
3. Acknowledge records a reason, never resolves or changes balances. Resolve requires later complete MATCH on the same account and affected current evidence; reject stale matches or cross-account evidence.
4. Repeated identical evidence does not flood incidents. A new discrepancy after resolution creates a new incident; old comparisons/status history stay readable.
5. Expose an accounting-readiness result for later D39 wiring. No kill-switch write or automatic broker action is introduced.

## Acceptance tests

- Seeded comparable discrepancy creates OPEN, duplicate processing creates one incident, acknowledgement leaves it unresolved.
- Admin resolve with later valid MATCH succeeds; missing/stale/cross-account evidence is refused.
- Trader/Viewer and deactivated Admin refused even with a historical replay time.
- Two concurrent transition writers produce one CAS successor; a simultaneous newer mismatch prevents stale resolution; a deactivation that takes its operator lock first prevents acknowledgement. Rollback leaves no partial audit/event; all history mutation SQL refused.
