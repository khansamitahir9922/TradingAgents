## Contracts

The [M5 shared contracts](M5-README.md#shared-contracts) and accepted ADR-010 govern this task. Proposed rules for this task:

1. Add immutable broker snapshots in public storage and simulator-private account opening/action/execution evidence in schema sim_broker; only the worker-role snapshot store writes the public evidence.
2. Simulator seed is an immutable audited RESEARCH-only setup command in the public database, referencing the declared start; only the worker consumes it into the private simulator account. Core never calls a seed method or writes private sim state. Never read internal ledger, OMS fills or provisional portfolio to calculate broker cash/holdings. Shared raw source data is allowed; shared posting implementation is not.
3. Expose broker.snapshot(account_id, at=...) -> neutral BrokerSnapshot. Return explicit unavailable coverage for legacy unscoped accounts or missing state. No new mandatory external adapter exists in M5.
4. Follow C4 for taken/received times, completeness, units, reported open orders and execution references. Broker values are stored unchanged, never adjusted to make comparisons pass.
5. The private simulator records its own executions exactly once and applies its own known corporate-action sequence; missing pay dates remain unpaid receivables. Existing materialize/submit/cancel outcomes remain unchanged. Actual worker scheduling/writes are wired in M5-10.

## Acceptance tests

- Hand-calculate broker cash and shares after opening, BUY/SELL fees, split, dividend and cancellation.
- Mutating internal ledger/OMS fill evidence does not change broker snapshot values; mutating broker-only evidence produces a detectable difference.
- Two accounts remain isolated; an unscoped or wrong-account snapshot cannot appear as a complete empty portfolio; public setup commands are immutable/idempotent and refused for PAPER accounts.
- Partial/unknown cash basis or missing positions/order coverage is INCOMPLETE; future action/revision or execution never leaks before cutoff.
- Public snapshot UPDATE/DELETE/TRUNCATE and wrong-role insert are refused; repeat capture of identical evidence is idempotent.
