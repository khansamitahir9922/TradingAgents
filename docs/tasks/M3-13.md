## Goal
Let a named Admin or Trader approve or decline one exact intent version before it expires, audited, with the deadline enforced atomically (G1 step 9; PRD UC-04, partial; design principles D-14 – D-16).

## Allowed files
- `investment_engine/oms/approvals.py` (new)
- `investment_engine/admin_cli.py`: `intents approve|decline|expire` commands
- `tests/engine/test_approvals.py`, `tests/engine/test_admin_cli_intents.py` (new)
- `docs/tasks/M3-13.md`, `PROGRESS.md`

## Contracts
```python
def approve(intent_id: str, version: int, *, operator_id: str, at: datetime, stores: ControlStores,
            calendar, reason: str = "") -> StoredIntent
def decline(intent_id: str, version: int, *, operator_id: str, at: datetime, stores: ControlStores,
            reason: str) -> StoredIntent
```
CLI: `intents approve ID --version N --operator OP [--at T]`, `intents decline ID --version N --operator OP --reason TEXT [--at T]`, `intents expire --account A [--at T]` (one account, R3) and `intents expire --paper` (all PAPER accounts, live time only).

`approve` and `decline` take `at` (business time: replay for RESEARCH, live for PAPER) and `command_at` (always the injected LiveClock), and record both.

## Rules
1. **The exact version** (Law 12; D-14). `--version` is required. Approval refuses when it isn't the latest version, the state isn't AWAITING_APPROVAL, or `at >= approval_deadline` (D11). Each refusal states why and changes nothing.
2. **Who** (D17; PRD §4; Codex re-review R2). The operator must be an active ADMIN or TRADER at the **real command time** (`command_at`, LiveClock), never at the replay time; a VIEWER, or an operator inactive now, is refused whatever `--at` says. Everything about the intent (deadline, autonomy setting, limits and rules versions, halt) is checked at the business time `at`. `approved_at = at`; the command time is stored as `approval_recorded_at` and in the audit event (`at` = command time, `business_at` = replay time, M3-04 rule 5). The account's autonomy setting at `at` must be **the same setting** (`setting_id`, M3-05) as the one recorded in the intent's lineage, and it must be Level 1. Any change since the proposal is refused with "autonomy changed since proposal", including 1 -> 2 -> 1, which ends at the same level with a different setting (Codex S4). Likewise, a risk-limits or policy-rules version different from the intent's (`risk_version`, `policy_version`), or an active halt for a BUY, refuses with "controls changed since proposal; propose again".
3. **Atomic and serialized with control changes** (S4). The approval transaction first takes the account-control lock (M3-05 rule 6). Under it, it reads the operator, the autonomy setting, the limits and rules versions and the halt state, checks the deadline, and makes the transition with compare-and-set (M3-09). An autonomy change, limit publish or halt therefore commits either entirely before the approval, which then sees it and refuses, or entirely after it. The intent's compare-and-set alone doesn't serialize these unrelated control rows; the lock does. If expiry or another approval wins the race, the command reports `StaleWrite` as "intent changed meanwhile; nothing approved". Approval sets `approved_by`, `approved_at = at` and `approval_expires_at` = the close of `target_session`, but never later than the view's `valid_until` (D10, D11).
4. **Time.** For a PAPER account the CLI uses a LiveClock, and `--at` is refused. For a RESEARCH account `--at` is required; it's a replay time and must be at or after the intent's `created_at`. Its output is labelled "SIMULATED (replay time)". No other path supplies a time.
5. **Decline** needs a reason. **Expire** (R3): `--account A` runs `expire_due(A, at)` for that account only. RESEARCH requires `--at`; PAPER refuses it and uses the LiveClock. `--paper` runs `expire_paper_due` across PAPER accounts on live time and never touches RESEARCH accounts. The command lists what expired.
6. **Output** prints the version being acted on in full (side, quantity, order type, limit price, TIF, reference price, target session), its policy and risk results, any reduction, the deadline in UTC and exchange time, and "No order is created in M3". ASCII only.
7. Every success and every refusal attempt is audited: refusals as `intent.approve_refused` with the reason, written in their own transaction.

## Acceptance tests
- Approve happy path (Trader and Admin) with the expiry computed from the calendar, including a half-day close.
- Refusals: wrong version, old version after a reduction, not awaiting, deadline passed (exactly at the deadline too), Viewer, inactive operator, autonomy changed. Each changes no state and writes one refusal event.
- Race on PostgreSQL: approve vs expire at the deadline boundary, and two approvals: one wins, the other reports the stale write.
- Race on PostgreSQL, approve vs `set_autonomy` (and vs `limits publish`), 50 repetitions: either the change commits first and the approval is refused, or the approval commits first. Never an approval under a setting that was already superseded.
- Autonomy 1 -> 2 -> 1 between proposal and approval is refused; equal `effective_at` values are resolved by `sequence`; a newer limits or rules version, or a halt for a BUY, refuses approval.
- PAPER refuses `--at`; RESEARCH requires it and labels the output.
- **R2, through the CLI:** an operator bootstrapped today approves a 2021 research intent before its simulated deadline and succeeds. An operator deactivated today, or a Viewer, is refused even with an earlier `--at`. The display and audit show the real command time and the simulated approval time.
- **R3:** `intents expire --account A --at T` changes only A; `--paper` changes no RESEARCH intent; PAPER with `--at` is refused.
- Decline without a reason is refused; with one it's DECLINED and audited.

## Out of scope
Dashboard approval cards (M8), order creation after approval (M4), notification of pending approvals.
