## Goal
Store each walk-forward evaluation run immutably in the Operational Database's evaluation domain, so every reported number can be reconstructed from its recorded configuration, folds, references and versions.

## Allowed files
- `investment_engine/evaluation/run_store.py` (new)
- `investment_engine/storage/schema/0003_evaluation.sql` (new)
- `investment_engine/storage/schema/0004_append_only_insert_guards.sql` (new; **scope extension approved by the owner on 2026-10-15** for Codex's M2 review finding B1: BEFORE INSERT guards on `lineage_records` and `evaluation_records` so INSERT OR REPLACE / REPLACE / OR IGNORE can't overwrite a stored id. It also protects M2-07's lineage table; forward-only, so existing schema-3 databases gain it on upgrade. No ADR needed.)
- `tests/engine/test_lineage.py` (B1 replacement regressions only)
- `tests/engine/test_evaluation_run_store.py` (new)
- `tests/engine/test_sqlite_store.py` (schema-version/migration assertions only, preserving M1 coverage)
- `docs/tasks/M2-11.md` (status), `docs/tasks/M2-11b.md`, `PROGRESS.md`

## Contracts
`EvaluationRunStore.append` and `EvaluationRunStore.get` exactly as in [M2-11](M2-11.md).

## Rules
[M2-11](M2-11.md) rule 5: IDs hash canonical content; an identical append is a no-op, a conflicting ID raises; SQL triggers reject UPDATE and DELETE; migrations use the existing numbered loader. Since B1: inserts of an existing id are refused at the schema boundary too (migration 0004), independent of the connection's recursive-trigger setting.

## Acceptance tests
[M2-11](M2-11.md) acceptance case 5: reconstruction of config and references, append idempotence, conflict rejection, direct-SQL immutability, migration of an existing database, installed-schema smoke check.

## Out of scope
