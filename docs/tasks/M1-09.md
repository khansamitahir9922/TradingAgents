## Goal
Implement the `CorporateAction` contract from Part H (`SPLIT`, `DIVIDEND`, `SYMBOL_CHANGE`, `DELISTING`), with provider-scoped identity and revisions. It uses the **same availability rules as candles**, so a replay can't see an action, or a correction to one, before it was available.

## Contracts
```python
class ActionType(StrEnum): SPLIT, DIVIDEND, SYMBOL_CHANGE, DELISTING
class AmountBasis(StrEnum):
    AS_REPORTED                          # the provider's amount is verified as declared (as-paid)
    RECONSTRUCTED_FROM_SPLIT_ADJUSTED    # rebuilt to as-paid terms by a verified reconstruction (M1-12)
    NO_LATER_SPLIT                       # used unchanged; no split between ex-date and download

@dataclass(frozen=True)
class CorporateAction:
    source: str                      # PROVIDER id (M1-08 PROVIDER_ID_PATTERN); part of identity
    instrument_id: str
    action_type: ActionType
    ex_date: date                    # exchange-local date
    ratio: Decimal | None            # SPLIT only: new shares per old share (e.g. Decimal("10"))
    amount: Money | None             # DIVIDEND only: per share, quantum PRICE_QUANTUM
    amount_basis: AmountBasis | None # DIVIDEND only
    new_symbol: str | None           # SYMBOL_CHANGE only
    source_version: str; import_id: str
    received_at: datetime            # UTC; observation by this system
    processed_at: datetime           # UTC
    revision: int                    # numbered per identity
    available_from: datetime         # UTC
    availability_basis: AvailabilityBasis

    @property
    def identity(self) -> tuple[str, str, ActionType, date]:
        return (self.source, self.instrument_id, self.action_type, self.ex_date)
```

## Rules enforced by the contract
- Exactly the fields for the action's type are set, and the others are `None`.
- `ratio > 0` and `ratio != 1`. `amount > 0`.
- `source` matches the provider pattern.
- **The same availability rules as candles (M1-08 rules 4–7):**
  - `OBSERVED` ⇒ `available_from == received_at`;
  - `revision >= 2` ⇒ `OBSERVED`;
  - `BACKFILL_ASSUMED` ⇒ `revision == 1`.

## Implementation choices
**Resolved**
- **Backfill availability is the start of the ex-date** (00:00 in the instrument's exchange time zone, stored in UTC), labelled `BACKFILL_ASSUMED`. Announcements come before the ex-date, but the source gives no announcement time. So the ex-date is assumed as the latest point at which the action must be known, and the label says so. The importer (M1-12) computes it, and the contract checks consistency.
- **Corrections** (a changed ratio or amount found on a later import) are new `OBSERVED` revisions, available from their own observation time and **never backdated**.
- **The provider is part of the identity.** The same split reported by two providers is two records, not a revision.

**Unresolved:** none.

## Acceptance tests
- A valid action of each type. Wrong field combinations are rejected per type.
- The availability rules: a backdated revision 2 is rejected, and `BACKFILL_ASSUMED` with revision 2 is rejected.
- A dividend amount needs `Money` in the instrument's currency at `PRICE_QUANTUM`.
- **Two providers:** the same split from `yfinance` and `testvendor` has different identities.
- `CorporateAction` is immutable.
