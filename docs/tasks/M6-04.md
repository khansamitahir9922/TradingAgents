## Contracts

The [M6 shared contracts](M6-README.md#shared-contracts) govern this task.

1. `ResearchPort.run(job, *, clock) -> RunOutput` builds `TradingAgentsGraph` from the job's frozen settings (pinned models, `llm_max_retries=0`, checkpointing off, results directory under the worker's data dir) and the M6-00 callback.
2. Capture: every LLM call's messages and response, every tool call/result, data-vendor/endpoint/fetched_at references, final state (reports, structured objects from M6-03), upstream version and repository code version, warnings, usage.
3. Ticker comes from the existing SymbolMapping for the instrument; the run date must equal the current exchange date (D50) or the job is refused before any LLM call.
4. Exceptions are captured as outcome FAILED with type and sanitized message; secrets are never captured (prompts are scanned for the loaded key and redacted, with a test).

## Implementation/check record

TradingAgentsAdapter behind the ResearchPort: builds the upstream graph from the job's frozen settings (pinned models, llm_max_retries=0, checkpointing off, results/cache/memory under the worker's work directory) and runs the compiled graph itself with the M6-00 counter and a TextCapture handler in both model and graph config, so model and tool calls are all seen. It captures every prompt, response, tool input and tool output (verbatim untrusted text, cut beyond 1,000,000 characters with the cut recorded), the selected final state including the U1 structured objects, the upstream and repository versions and usage. Data-source references name the upstream router, since upstream picks the vendor per tool. A research date other than the current New York exchange date is refused before any model call (D50). A provider error becomes a FAILED record with no context. Loaded secrets are redacted from every captured text, the state JSON and the failure message.

Owner-approved scope extension (2026-10-26, answered in session): the M1 layering rule "the package never imports tradingagents" now allows exactly `investment_engine/research/adapter.py`, as ADR-001 specifies one adapter. A new rule keeps LangChain/LangGraph and the research runtime modules (adapter, capture, usage) inside `investment_engine/research`. ## Implementation/check record

Codex review B3 (ambient TypeSafe key switches on excluded Jev calls) and B4 (job settings didn't pin the actual provider/endpoint), fixed together, as they share one allowlist. The adapter now sets every run-shaping upstream key explicitly: both tier providers to the job's provider, every backend URL to none, reasoning/thinking knobs and output cap to their defaults, upstream's own tool/recursion limits, no benchmark. It refuses any provider but Google (D45) before a call, and records the effective configuration (`ResearchRecord.effective_config_json`, a new field with a default). Ambient switches are refused, by name only, never value, both at worker startup and again by the adapter before any call: TypeSafe/Jev variables (on whatever the provider; D54), the Google client's Vertex AI selectors (another endpoint, project and billing), and every `TRADINGAGENTS_*` override except the three paths the adapter replaces. `GEMINI_API_KEY` (Google's fallback key name) joins the keys that may live only in `research_worker.env`. Other providers' keys and endpoints are inert once both tiers are pinned to Google, so they aren't refused; the test suite's own placeholder keys confirmed this would otherwise refuse harmless setups.
