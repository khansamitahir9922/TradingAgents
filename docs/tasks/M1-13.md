## Goal
Import NVDA daily and hourly bars from yfinance (research-only data; Part D). Apply **each field's verified transformation** from M1-12, with `F(d)` computed from the **complete split history over the verified date range** (M1-12: every split with `ex_date >= verified_from`, equal to `cited_splits`), and store them with honest provenance:
- per-field bases (`price_basis`, `volume_basis`);
- `BACKFILL_ASSUMED` availability for first-seen history.

## Contracts
```python
@dataclass(frozen=True)
class BarImportReport:
    write: WriteResult
    dropped_forming: int                         # bars with end_time > their download's received_at; not stored
    rejected: list[tuple[datetime, str]]         # (vendor timestamp, reason)
    covered: tuple[datetime, datetime] | None    # first start_time, last end_time actually stored
    split_history: tuple[tuple[date, Decimal], ...]   # the in-range history used for F (ex_date >= verified_from)
    max_split_factor_applied: Decimal

def import_bars(instrument_id: str, timeframe: Timeframe, start: date, end: date, *,
                clock: Clock, resolver: SqliteSymbolResolver, instruments: SqliteInstrumentRepository,
                calendar: TradingCalendar, reader: MarketDataReader, writer: MarketDataWriter,
                fetch_bars=<yfinance bar fetch>, fetch_split_history=<yfinance full-history fetch>,
                backfill_latency: timedelta = timedelta(0),
                verification: VerificationRecord = YAHOO_VERIFICATION) -> BarImportReport
```
**v0.2.3 details:** `end` is **exclusive**, as in yfinance (`start <= session date < end`). `instruments` supplies the instrument's currency (never a default). `verification` defaults to M1-12's record and lets tests use synthetic records; an instrument other than its `instrument_id` is refused before any fetch.

## Steps
1. **Transformations.** Look up the price and volume transformations for the timeframe with `transformation_for` (M1-12). A blocked field stops the import before anything is fetched. **v0.2.1:** a request with `start < YAHOO_VERIFICATION.verified_from` (2019-01-01 for NVDA) is also refused here, before any fetch (M1-12, "Verified date range").
2. **Symbol.** Resolve it via SymbolMapping (`provider = "yfinance"`) for the included dates (`start <= date < end`, never the excluded `end`). If the mapping changes inside the range, split the request at the boundary. Segments with no calendar sessions need no bar fetch.
3. **Split history before.** Fetch the **complete** split history (the M1-12 full-history call), as `split_history_before`. The call is full-history so that no in-range split is missed; only splits with `ex_date >= verified_from` are then used (steps 6–7).
4. **Bars.** Fetch with `auto_adjust=False, actions=False, repair=False, back_adjust=False, prepost=False`. Record `received_at = clock.now()` when the download completes.
5. **Split history after.** Fetch it again. It must equal `split_history_before`, or the import aborts.
6. **Agreement with storage.** ~~over the whole history~~ **v0.2.1: over the verified date range** (M1-12). Two checks, and either failing aborts the import before anything is written:
   - the vendor's splits with `ex_date >= verified_from` must equal `YAHOO_VERIFICATION.cited_splits`;
   - they must also equal the stored `yfinance` `SPLIT` actions with `ex_date >= verified_from`, from `reader.actions_latest(source="yfinance", …, types={SPLIT})`. A difference aborts with instructions to run the action import (M1-12) first.

   Splits before `verified_from` are never compared, used or stored. **The split events inside the bar response are never used**: yfinance filters them to the requested dates.
7. **`F(d)`** is computed per bar from the complete in-range history, up to the download date. That includes **every split after the requested window**. Because `start >= verified_from` (step 1), no split before the range can affect any bar.
8. **Timestamps to sessions**, using the calendar:
   - **Daily:** the vendor date → that session's open and close (UTC). A non-session date is rejected and reported.
   - **Hourly:** the vendor timestamp is the bar start in `America/New_York`. `end_time = min(start + 1h, session close)`, so the regular day's last bar is 15:30–16:00 and half-days end at 13:00. A bar starting outside a session is rejected and reported.
9. Drop bars whose `end_time > received_at` of the download that delivered them: they were still forming when received, however late processing ends (v0.2.4, Claude Code review B1). A bar received exactly at its `end_time` is kept. Dropped bars are counted, not stored.
10. **Apply the transformations per field.**
    - `SPLIT_RECONSTRUCTION` → reconstruct with `F(d)`.
    - `IDENTITY` → use the value unchanged.
    - `IDENTITY_IF_NO_LATER_SPLIT` → use it unchanged only if `F(d) == 1`. Otherwise **reject that bar** and report it.

    Then quantize, and set `price_basis` and `volume_basis` to match.
11. **Build observations** with `source = "yfinance"`, `source_version` set to the yfinance version, and `backfill_available_from = end_time + backfill_latency`. Write through `MarketDataWriter`, which assigns revisions per provider and never backdates.

## Implementation choices
**Resolved**
- **Default ranges:**
  - **daily** from 2019-01-01;
  - **hourly** from the earliest date yfinance serves, and never before `verified_from` (step 1). The actual first bar is reported in `covered`; nothing is assumed.
- **The vendor daily series is the daily series of record in M1.** Resampled daily bars (M1-15) are a cross-check only.
- **Re-import is idempotent.** If a later split makes Yahoo re-adjust history, reconstruction with the new complete history gives the same as-traded values, so the writer records `unchanged` rather than a storm of revisions. **v0.2.1:** a new split first stops imports (step 6) until its citation is added to `cited_splits` and reviewed. After that, re-import is idempotent as described.

**Unresolved**
- **How far back hourly history reaches.** It's measured by the `integration` check and recorded.

## If verification blocks
Follows M1-12's rule. A blocked field blocks this task for that timeframe, and blocks M1 completion. A proposed ADR alone doesn't unblock it.

## Acceptance tests (fixtures)
**Later split outside the window (Codex finding 1; v0.2.3, option B).** A daily request for **2021-07-01 → 2021-07-20, with 2021-07-20 excluded** (`end` is exclusive):
- the window ends before the 2021-07-20 split, so the bar response has no split events, while the in-range history (from `verified_from`) has exactly 2021-07-20 (4:1) and 2024-06-10 (10:1), equal to `cited_splits`;
- every bar gets `F = 40`;
- the stored 2021-07-19 close matches the cited **$751.19** (`FOOL-2021-07-20`) within $0.01;
- no bar on or after 2021-07-20 is stored.

**Date-filtered requests miss later splits (demonstration).** The recorded 2021-Q1 request with `actions=True` (`nvda_1d_2021q1_with_actions.json`) has **0** split events, although splits followed on 2021-07-20 and 2024-06-10. A test asserts this, so a date-filtered response is never mistaken for the split history. *(The archived MarketWatch closes inside 2021-Q1 stay in `nvda_reference.json` as supporting evidence; no test depends on them.)*

**Forming daily bars (v0.2.4, review B1).** The 2026-10-09 bar (close 20:00 UTC): received 2 s before the close → dropped; received before the close while processing crosses it → dropped; received exactly at the close → kept; received after the close → kept, with `received_at >= end_time`.

**Window across a split.** A daily request across 2024-06-10: stored closes show the ~10× step on the ex-date while the vendor's raw columns don't, and the anchor matches.

**Split-history checks:**
- the before and after histories differ → abort;
- the history differs from the stored actions → abort;
- the bar response's own split events are ignored (a test plants a misleading one).

**Verified date range (v0.2.1):**
- a request with `start` before `verified_from` (e.g. 2018-12-31) raises **before any fetch**: the fake fetchers record no call, and nothing is written;
- the stored actions hold only the in-range splits, while the vendor history also has the 2000 – 2007 splits, including the 2001 non-session date. The import **proceeds**, because pre-range splits are never compared;
- an in-range split missing from storage, an extra planted in-range split, or a different in-range ratio **aborts**;
- a vendor in-range split that isn't in `cited_splits` (a new split since verification) **aborts**, even when storage agrees with the vendor;
- a window ending before a later in-range split still applies that split's factor.

**Hourly:**
- bar boundaries per step 8, including a half-day;
- a planted pre-market row is rejected;
- a planted bar ending after its download's `received_at` is dropped;
- under `IDENTITY_IF_NO_LATER_SPLIT`, a bar with `F > 1` is rejected and reported.

**Per-field bases.** A synthetic verification with reconstructed prices and identity volume gives `price_basis = RAW_RECONSTRUCTED_FROM_SPLIT_ADJUSTED` and `volume_basis = RAW_AS_REPORTED`.

**Re-import:**
- the same fixture → all `unchanged`;
- a fixture re-adjusted for a hypothetical new split, with that split in the history, the store **and a test verification record's `cited_splits`** → all `unchanged` (v0.2.2: without the citation, the import aborts per step 6);
- one changed close → one `OBSERVED` revision 2.

**Other cases:**
- A blocked field stops the import before any fetch.
- Every stored candle has `source = "yfinance"`, both bases, `BACKFILL_ASSUMED` (revision 1), and `available_from >= end_time`.
- `integration` (not run by default): a live fetch matches the fixture's column semantics, and hourly coverage is reported.

Other instruments; minute bars; live or production data (M7).
