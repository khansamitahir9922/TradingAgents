## Goal
Create the empty platform package beside `tradingagents/`, with guard tests for its boundaries. **Before changing anything**, record the repository's exact test baseline, so every later task can say precisely which existing tests pass and fail.

## Dependencies
M0 merged into `main`. OPEN-01 (package name) is answered by the owner at the start of this task.

## Allowed files
- `investment_engine/__init__.py` (new)
- `tests/engine/__init__.py`, `tests/engine/test_layering.py` (new)
- `docs/baselines/M1-00-baseline.md` and raw outputs `docs/baselines/M1-00-*.txt` (new)
- `pyproject.toml`: **only** `[tool.setuptools.packages.find] include`
- `.github/workflows/ci.yml`: **only** the smoke step's `python -c "import …"` line
- `docs/tasks/M1-00.md`, `PROGRESS.md`

## Contracts
- `investment_engine/__init__.py` defines `__version__ = "0.0.0"` and nothing else. Importing the package has no side effects (no I/O, no environment reads).
- **Layering rules**, enforced by `tests/engine/test_layering.py` with an AST scan in the style of the existing `tests/test_layering.py`:
  1. Nothing in `investment_engine/` imports `tradingagents` or `cli` (Part I; roadmap 1.2).
  2. `yfinance` is imported only under `investment_engine/market/importers/`.
  3. `pyarrow` and `duckdb` are imported only under `investment_engine/market/store/`.

  Rules 2 and 3 hold trivially until those folders exist. They're written now so they guard from the first line of code.

## Implementation choices
**Resolved**
- **Package name:** `investment_engine`, if the owner confirms OPEN-01. It must never be `platform`, which shadows the standard library.
- **Test location:** `tests/engine/`, not `tests/investment_engine/`. A folder with the same name as the package invites import confusion.
- **The baseline is recorded before any change**, on `main` at the merge commit of M0.

**Unresolved**
- **OPEN-01 (owner).** If the owner picks another name, use it everywhere these specs say `investment_engine`.

## Baseline procedure (recorded in `docs/baselines/M1-00-baseline.md`)
Record the git commit, branch, OS version, the venv's Python version, and `pip --version`. Then run, saving each full output to `docs/baselines/M1-00-<name>.txt`:

| Name | Command |
|---|---|
| `install` | `.venv/Scripts/python.exe -m pip install -e ".[dev]"` (installs ruff and the test extras the CI uses) |
| `pytest-gitbash` | In Git Bash: `.venv/Scripts/python.exe -m pytest -q` |
| `pytest-powershell` | In PowerShell: `.venv\Scripts\python.exe -m pytest -q` |
| `ruff` | `.venv/Scripts/python.exe -m ruff check .` |
| `smoke` | In a fresh scratch venv (`py -3.11 -m venv <scratch>`), install the package without extras (`<scratch>/Scripts/python.exe -m pip install .`), then run the CI smoke import: `python -c "import tradingagents, cli.main; print('clean-install import OK')"` |
| `pytest-py314` *(optional)* | The same pytest run in a scratch Python 3.14 venv with `.[dev]` installed |

For each run, record:
- the summary line (passed, failed, skipped, deselected, errors);
- **every failing test ID** with its first error line.

Then state explicitly, for each of the two earlier-reported Windows failures (`test_yfinance_keeps_its_cache_out_of_the_users_home`, `test_every_command_is_registered_when_run_as_a_module`), whether it was **reproduced** or **not reproduced**, and in which shell.

Also record what **couldn't** be reproduced locally: Python 3.12 and 3.13, and the CI `TZ=America/New_York` job.

## Acceptance tests
1. `tests/engine/test_layering.py` has the three rules, and they pass.
2. A unit test imports `investment_engine` and checks `__version__`.
3. After the change, the baseline commands are rerun:
   - every test that passed in the baseline still passes;
   - the failing set is the recorded baseline set, listed by ID (no new failures);
   - `ruff check .` passes;
   - the smoke import, extended to `import tradingagents, cli.main, investment_engine`, succeeds in a fresh no-extras install.
4. `PROGRESS.md` records the commands, results and every unresolved failure. CI is recorded as "not yet run" until the owner pushes.

## Out of scope
- Any module code beyond `__init__.py`.
- New dependencies.
- Fixing the pre-existing failures. Each is listed as unresolved; fixing one would be its own task, touching existing tests or code only with the owner's approval.
- Changing the CI matrix or jobs, beyond the one smoke-import line.
