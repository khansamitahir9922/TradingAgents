## Contracts
```python
class Side(StrEnum): BUY = "BUY"; SELL = "SELL"
class IntentState(StrEnum):
    PROPOSED; POLICY_REJECTED; RISK_REJECTED; SUPERSEDED; AWAITING_APPROVAL; APPROVED; DECLINED; EXPIRED; CONVERTED

@dataclass(frozen=True)
class OrderIntent:                     # Part H fields, plus what M4's gate needs to check "still current"
    intent_id: str; version: int; account_id: str; instrument_id: str
    side: Side; quantity: Decimal      # whole shares, > 0
    order_type: str; limit_price: Decimal; time_in_force: str     # "LIMIT", "DAY" (D7, D13)
    reference_price: Decimal; reference_bar: BarRef               # from RawReference (M3-07): the decision bar's raw close
    target_session: date               # the next regular session after the view's T
    view_lineage_id: str; view_valid_until: datetime
    snapshot_id: str; sizer_version: str; policy_version: str; risk_version: str
    created_at: datetime
    supersedes: int | None             # the version this one replaces (risk reduction), else None
    MATERIAL = ("account_id", "instrument_id", "side", "quantity", "order_type", "limit_price", "time_in_force")

@dataclass(frozen=True)
class SizingResult:
    intent: OrderIntent | None; reason: str      # no intent: why (ABSTAIN, NEUTRAL, already at target, ...)

def size(view: MarketView, *, view_lineage: LineageRecord, reference: RawReference, snapshot: PortfolioSnapshot,
         limits: RiskLimits, rules: PolicyRules, calendar, at: datetime, sizer_version: str) -> SizingResult
```
State, approval fields, decisions and `aggregate_version` live in the intent store (M3-09), not in this immutable value.

```python
@dataclass(frozen=True)
class CheckResult: name: str; passed: bool; reason: str          # reason always set, also when passed

@dataclass(frozen=True)
class PolicyDecision:
    intent_id: str; intent_version: int; passed: bool
    checks: tuple[CheckResult, ...]; policy_version: str; autonomy_level: int; decided_at: datetime

class RiskOutcome(StrEnum): APPROVE = "APPROVE"; REJECT = "REJECT"; REDUCE = "REDUCE"

@dataclass(frozen=True)
class RiskDecision:
    intent_id: str; intent_version: int; outcome: RiskOutcome
    checks: tuple[CheckResult, ...]; risk_version: str; snapshot_id: str
    reduced_quantity: Decimal | None      # set only for REDUCE
    decided_at: datetime

@dataclass(frozen=True)
class NotRun:                             # a check that was not executed, and why (Codex B3)
    stage: str                            # "policy" or "risk"
    reason: str                           # e.g. "policy rejected: risk not evaluated"
```
All three are registered with the canonical codec so they can be stored, hashed and audited. A `NotRun` is never shown or counted as a pass or a failure.

## Rules
1. **Identity.** `intent_id = "int-" + SHA-256(account_id, view_lineage_id, instrument_id, sizer_version)`, so re-running the pipeline for the same view and account finds the same intent, never a duplicate. Version 1 is the sizer's; later versions come only from risk reductions (M3-11).
2. **Targets (long only, D2).** BULLISH: target value = `max_position_fraction` × equity. BEARISH: target 0 (sell everything held; nothing to do if flat). NEUTRAL: hold, no intent. ABSTAIN or an expired view: no intent, with the view's reason (Law 9). Strength isn't used to scale size: it's a heuristic scale, not a probability (M2-04).
3. **Quantity.** BUY quantity = floor((target − current value) / limit price) in whole shares; SELL quantity = the shares held when the target is 0. Less than one share gives no intent ("below one share"). Quantities and prices are Decimal.
4. **Prices** (Codex B1). `reference_price` and `reference_bar` come only from the supplied `RawReference` (M3-07 rule 1); its source, instrument and bar must match the view's lineage, or `size` raises. The current value of a holding is `snapshot.held(instrument) × reference.close`; when the instrument is held, the snapshot's `price_ref` must be the same bar revision, otherwise `size` raises (the pipeline treats that as a prerequisite failure). A cash-only account needs no position to size its first BUY. No adjusted or float value enters. `limit_price` = reference × (1 ± `limit_band_fraction`), rounded to the cent toward the safer side (down for buys, up for sells). TIF and order type come from PolicyRules.
5. **Session.** `target_session` is the next regular session after the view's T (calendar). Views must be D1 (D12).
6. **Determinism.** No clock reads; `created_at = at`. Same inputs give an identical intent. Floats never enter quantities or prices.
7. `CONVERTED` exists in the enum for M4's contract, but nothing in M3 can produce it (M3-09 rule 4).

## Acceptance tests
- Hand-calculated BUY sizes at several equities and prices, including floor rounding, the exactly-one-share and below-one-share cases.
- BEARISH with and without a position; NEUTRAL; ABSTAIN; expired view; already at target: each with its reason.
- **First BUY from the default cash-only account**, sized from the RawReference alone; a held-position SELL; a reference from another provider, instrument or revision raises; a held position valued from a different bar revision than the reference raises.
- Limit rounding direction for buys and sells.
- The same inputs give the same id and fields; a different sizer version gives a different id.
- `OrderIntent` is frozen and refuses fractional or non-positive quantities, non-UTC times and floats.

## Out of scope
Policy and risk checks (M3-10, M3-11), storage and state changes (M3-09), orders (M4), volatility-based sizing (later, versioned).
